# SURGE Mark.2

## 概要

LiDAR・カメラ・強化学習・模倣学習・SLAMなど10種類以上の自動運転を1台に搭載。同じ車・同じ安全機構で手法を入れ替え、実機で比べられるミニカーです。

## システム構成

### 全体構成

車体（Raspberry Pi 5 + STM32）と、PC側の3つのツール（GUI・シミュレータ・校正ツール）で構成しています。詳細は添付の構成図を参照してください。

役割を3階層に分けています。上位のPiやPCが止まっても、STM32が車両を安全に停止させます。

| 階層 | 担当 |
|---|---|
| STM32 | ミリ秒単位の制御と安全停止 |
| Raspberry Pi 5 | センサ統合、自動運転の判断 |
| PC | 操作・可視化・解析 |

### デバイス

| 機器 | 用途 |
|---|---|
| Raspberry Pi 5 | 自動運転の判断、地図作成、ログ記録 |
| STM32F446RE | モータ制御、トラクションコントロール（空転抑制）、トルクベクタリング（左右の駆動力配分）、安全停止 |
| LiDAR LD06 | 周囲の距離計測（地図生成、自己位置推定、障害物検知） |
| カメラ IMX219 ×2 | 前後の映像取得（走行可能領域・白線の認識、模倣学習の入力） |
| IMU MPU6050 | 角速度・加速度の計測 |
| 超音波センサ RCW-0001 ×2 | 前後の近距離障害物検知 |
| 絶対角エンコーダ AS5600 | 車速の計測 |
| BLDCモータ ×3 | 左右後輪のインホイール駆動、ステアリング |
| 灯火類 | 車両状態の表示 |
| Ni-MH 9.6V 1600mAh ×2 ＋ バッテリー監視・DC-DCコンバータ | 駆動系・制御系の2系統の電源 |

### ソフトウェア・ツール

- **Raspberry Pi**：Python、ZeroMQ（プロセス間通信）、2D SLAM、強化学習（PPO / Stable-Baselines3）、ONNX、`picamera2`、`gpiozero` + `lgpio`
- **STM32**：C/C++（速度・舵角制御、電流・温度保護、通信途絶時の安全停止）
- **GUI**：React、TypeScript、Vite、WebSocket、Canvas 2D、uPlot、Zustand（車の操作、センサ表示、ログ取得）
- **シミュレータ**：実機の特性を再現し、LiDARを使った自動運転を試験
- **校正ツール**：走行ログから車の物理パラメータを取得、カメラ映像の歪み補正
- **ログ**：MCAP形式で記録・再生、Foxglove Studioで可視化

### 通信

- Raspberry Pi 5 ⇔ STM32：UART 1Mbps ＋ GPIOハートビート
- Raspberry Pi 5 ⇔ PC：Wi-Fi / Ethernet、WebSocket

## 開発の背景・ストーリー

### きっかけ

大学でロボティクスを学ぶ中で、自動運転の手法は数多くあるのに、「どれが、どんな場面に向いているのか」を同じ条件で比べる機会がありませんでした。論文や教科書の手法を、実際に走る1台の車で全部試して比べたい。車やモータースポーツが好きだったこともあり、そのための車を自分で作ることにしました。

### 特徴：1台で、いろいろな自動運転が走る

車を走らせる「頭脳」を差し替えられる作りにしていて、次のような方式を実装し、実機で動かしています。

| 考え方 | 例 |
|---|---|
| **LiDARで空いている方向を探す** | Follow the Gap、Disparity Extender（地図なしで壁を避けて走る） |
| **カメラで道を見る** | 走行可能領域の認識、白線のライントレース、カメラ画像から操舵を学ぶ模倣学習 |
| **強化学習** | シミュレータ上の試行錯誤で、LiDARから操舵・速度を直接出す方策を学習 |
| **SLAMで地図を作る** | SLAM（自分で地図を作りながら自分の位置を知る技術）で地図を作り、最短・最速の走行ラインを計算して周回。分岐のあるコースでは経路を選んで走る |
| **人や目的地に合わせる** | 前の対象への追従、クリックで指定した位置への自動駐車 |

最高時速は15kmです。

### こだわり・工夫

- **手法を公平に比べられる土台**：どの方式でも、センサの入力、車への指令、安全機構は共通です。モードを追加しても、車やGUIの作りを変えずに済みます。
- **安全を最優先に分担**：判断はRaspberry Pi、リアルタイム制御はSTM32と分けました。Piが固まる、通信が切れるといった異常でも、ハートビートの停止をSTM32が検知して車両を止めます。電源を入れただけで走り出す経路もありません。
- **シミュレータと実機をつなぐ**：実機の特性を再現したシミュレータで先に検証し、同じ走行ログで複数の手法を比較します。実装した全モードは実機で動作確認済みです。
- **ログから車を知る**：走行ログから車の物理パラメータを求める校正ツールを作り、制御とシミュレータに反映します。
- **走りながら学習する**：路面のグリップなど、日によって変わる条件は走行中に学習し、速度やラインに反映します。
- **ほぼ全て自作**：Raspberry Piやカメラなどの既製品以外は、モータドライバを含めて自作です。ファームウェアから上位ソフト、GUIまで、全て自分で設計しました。
- **一番の苦労は制御設計**：実機には教科書通りにいかない点が多くありました。
  - ステアリングは、モータの角度と路面の舵角が比例しません。実機で測った特性から換算式を作りました。
  - 車速センサは分解能が粗く、そのまま微分しても加速度が使えません。加速度計と組み合わせたカルマンフィルタで補いました。
  - 路面や車の状態は計算では分かりません。走行ログから車の物理パラメータを求める校正ツールを作り、測って確かめながら制御を作り込みました。

### 今後の展望

現在のE2E（入力から操舵を直接出す学習型の自動運転）は、LiDARだけ、またはカメラだけを入力にしています。次は、両方を組み合わせた本格的なE2E自動運転に挑戦します。LiDARは距離に強く、カメラは路面や白線などの見た目に強いので、互いの弱点を補えると考えています。同じ車・同じ環境で単独方式と比べ、効果を数字で確かめます。

### SURGE Mark.2にかける思い

**「自動運転の手法を、1台の車で全部走らせて比べる」ロボティクスの実験場です。**

地図を作って走る車も、カメラだけで走る車も、学習で走る車も、同じ車体の上で動きます。
学生が本気で作った、「手法を選べて、走りながら進化する自律走行ミニカー」です。

# 他車の追い抜き（追跡・予測・計画）

自分より遅い車を抜くための、追跡（`raspi/nav/obstacles.py` の `VelocityTracker`）・相手の予測と追い抜きの計画
（`raspi/nav/overtake.py`）・付いていく制御（`raspi/auto/slam2d_raceline.py`）の設計。2026-11-20〜21 に作り直した。
進み具合の正は [`../PROGRESS.md`](../PROGRESS.md)。

## 1. 結論（どこまで抜けるか）

**toyota2 で抜けるかは、コースの形と安全の決まりでほぼ決まる。** 抜くには、片側に「相手の半幅＋自分の半幅＋他車との
横の余裕（0.10m）＋α」≈ 0.36m 空いた区間の中で、相手に並んでから前に出るまでを終える必要がある。

    区間に要る長さ ≈ (付いていく車間 g ＋ 両車の長さ 0.77m ＋ 前後の余裕 0.2m) ÷ (1 − 相手の速さの比 k) ＋ 出入り 約 1m

toyota2（経路 A）の片側が空く区間は最長で約 6.8m（右 s≈15〜22m、左 s≈21〜4.5m）。付いていく車間 g は
「止まり切れる車間 0.35m ＋ 空走（`react_s` × 速さ）」で、2m/s で約 1m になる。

| 付いていく車間 g | 抜ける区間がある相手の速さ（自分比） |
|---|---|
| 1.0m（今の安全の決まり） | 0.66 倍まで |
| 0.6m | 0.73 倍まで |
| 0.35m | 0.77 倍まで |
| 0.2m | 0.80 倍まで |

- 手前で下がって勢いをつける（スリングショット）は効かない: 速く近づくほど止まり切れる車間が広がる（約 1.4m）
- 以前の「割り込みの車間」（0.3 秒 × 相手の速さ、約 0.8m）を足すと上限はさらに下がる（0.70 倍 → g=1m では抜けない）。
  回帰の追跡器が相手の速さを遅く見ていたための余裕で、EKF にして外した（§3）
- 0.66 倍より速い相手を抜くには、付いていく車間（安全の決まり）・前後や横の余裕・車の長さのどれかを変える判断が要る
- **車間 0.3m（空走なし）はバンビが許容した（2026-11-21）が、今の付いていく制御では安全に実現できず戻した**（§7）

### 1.1 2026-11-26 の見直し（上の結論を独立に確かめ直した）

- 上の「0.66 倍まで」は、相手が**自分の線の上**を走るときの toyota2 の形の限界として正しかった。0.7 倍・車間 0.8〜1.0m
  からは、左の窓（s≈20.7〜4.7m、約 5.9m）でも抜き切る候補は 1 本も無い（記録の場面を再生して、戻る長さを短い側まで
  含めても 0 本）。要る長さ ≈（車間 0.9 ＋ 0.97）÷ 速さの差 ≈ 7〜8m
- ただし**その手前の 0.55〜0.65 倍でも抜けない時間が長かった原因は形ではなく計画器・予測・制御の側**にあった（§4〜§6 の ★2026-11-26）:
  相手の前側の予測の広がりが実測の 3〜10 倍の固定値（20%）だった・軌跡に覚える点（見えている点の重心）が見え方で動いた・
  計画器の「今すでに車間の内側か」の判定が制御の保つ車間とずれていた・候補の時刻が横ずれした道のりを無視していた
- 調べた手段のうち効かなかったもの（入れていない）:
  - **道幅全体の時空間格子（動的計画法、TUM の graph-based planner 系）**を候補の作り方に足した。曲率を節点の差分で見る形
    では横へ 1 節点動くだけで 2m/s 以上は横加速度の上限を超え、5 次式の段で結ぶ形（TUM と同じ）に作り直しても、
    相手が自分の線の上に居る限り窓の長さが足りないことは変わらず、計算が 8 倍（平均 40ms）になった
  - 新しく仕掛ける計画だけ余裕を広げる決断のヒステリシス（前後 +0.15m・横 +0.04m）: 0.7 倍が理想化した検証でも抜けなくなった
  - 戻る区間の長さの選択肢を短い側まで広げる（`_lengths(...)[2:4]` → `[0:4]`）: 抜き切れる候補は増えない
- スリングショット（手前で下がって勢いをつける）は、制動の上限と加速の上限がほぼ等しい（2.9・3.1m/s²）ので、止まり切れる
  車間の増え（(v²−u²)/2a）が近づく間に稼げる距離（(v−u)²/2a）を必ず上回り、今の安全の決まりの下では効かない（式で確かめた）

## 2. 評価の仕方（検証器）

- `sim.bench --mover` の他車は、**planner の経路が替わったら今の位置のまま新しい経路へ乗せ替える**（`sim/moving.Mover.rebind`）。
  ★それまでは最初の経路（1 周目の出発点からの枝を含む 26.0m）に結んだまま走らせていて、定常の周回（21.8m）と線が分かれる
  所で他車が別の線を走っていた。直す前の「抜いた回数」「相手の線が横切る所での接触」の一部はこの作り物で、直すと旧来の
  追い抜きは**自分の 0.64 倍の相手でもほぼ抜けなかった**（120 秒で 0〜2 回、時間の 82〜100% が後ろに詰まる）
- 相手の速さの比は `--mover` の `K`（経路の速度プロファイルに掛ける）ではなく、他車の実際の 1 周と自分の他車なしの 1 周
  （経路 A で 8.26 秒）の比で見る
- 経路は固定する（`--routes` に経路 A だけ）。経路の自動選択で自分だけ短い周回に替わると比べられない
- ★シムの他車は「自車の**今の**経路 × K」で走る。1 周目は出発点からの枝を含む線（26m）を走るので、その周の相手の速さは
  定常の周回と大きく違う（s=4〜10m で 0.7 対 1.2〜1.5m/s）。相手の予測を「全部の観測の平均」で覚えると、この周の値に
  引きずられた（§4 ★2026-11-26）
- ベンチは 1 本ごとのばらつきが大きい（同じ設定で抜いた 0〜3 回）。比べるときは種を変えて 3 本以上
- 理想化した閉ループ（知覚・制御が完全、相手は自分の線を K 倍で走る）で計画器だけを測る道具を作業中に使った（リポジトリには
  入れていない）。★「通れない」のとき並んだまま線へ戻るなど実機の制御と違う所があり、接触の数は当てにならない。また作った
  直後は計画の速度の列を `% L` で読んで約 1 周先を参照し、加速の指令が出ていなかった（検証器の不具合で、計画が毎周期崩れて
  見えた）。最終の判断は `sim.bench` で行う

## 3. 追跡（`VelocityTracker`）

- **協調旋回（CT）モデルの EKF**。状態 `[px, py, vx, vy, ω]`、観測は検出の重心。速度を直交成分で持つ（向きと速さで持つ
  CTRV は止まった物で線形化が特異になる）
- 同じ検出の列での比較（記録を再生）: 向きの誤差 中央 28° → 4〜5°（カーブ）、速度ベクトルの誤差 0.87 → 0.30m/s、
  0.5 秒先の位置 0.65 → 0.35m、相手の速さ 真値の 0.87〜0.89 倍 → 0.97〜0.99 倍
- **1 台が 2 つの検出に割れたものはまとめる**（`_merge_split`）。割れたまま 1 対 1 で結ぶと、余った方が毎周期新しい追跡に
  なって静止物と出続け、動く車の位置に静止物が居ることになった（付いていく候補がそれに当たり "blocked" → 急減速）
- 出力: `vx, vy`（確かに動いているときだけ。二択で使う所向け）に加え、速度の推定値 `ex, ey` とその標準偏差 `sv`、
  一度でも確かに動いたか `moved`（粘り付く）。観測が溜まって動いていない物は `ex = ey = sv = 0`
  （EKF の速度の σ はプロセス雑音のため止まった物でも下がりきらない）

## 4. 相手の予測

- **相手の速さも場所の関数として覚える**（`line_profile` の 4 つ目以降。Predictive Spliner, Baumann ら 2024 と同じ考え）。
  覚えていない区間だけ「今の速さ ÷ 自分の線の速度」の比で伸ばす
- 予測の不確かさは実測から: 経路に沿った位置の誤差 p90 ÷ 予測で進んだ距離が、覚えた速さで約 0.2、比で約 0.3
  （`_GROW_LEARNED`・`_GROW_RATIO`）。**広げるのは相手の前側だけ**（抜く車に危ないのは相手が予測より速いときだけ。
  後ろに付いている間は毎周期引き直す）
- まだ動いたことの無い物（見え始め）は速度の σ で前後・横に広げる（上限 0.6m）
- 当たり判定は**予測が信頼できる範囲に限る**（横へ出始める時刻＋`_T_PRED_MAX` 5 秒まで。TUM の IAC の planner と同じ）。
  ★予測の上限で相手を止めて見ていたため、5 秒より後に着く点で付いていく候補が止まった相手に当たり、全部「重なる」だった

### ★2026-11-26 に直した予測

- **前側の広がりを実測にした**（`overtake.calibrate_spread`・`pred_spread`、制御が 1 秒に 1 回 `OvertakeConfig.grow_learned` で渡す）。
  直近 20 秒の観測を、それより前の観測で覚えた速さで 1・2・3 秒先まで予測し、前側の外れの p90 ÷ 予測で進んだ距離を使う
  （標本外。下限 0.03）。測れない間は従来の一定値 0.2。固定の 0.2 は、予測どおりに走る相手でも 3 秒先で約 1m 前へ広げ、
  抜き切って前へ戻る所が確かめられなかった。ベンチの実測は 0.03〜0.14
- **場所ごとの速さは直近 3 回の観測の中央値**にし、経路に沿って ±0.4m で均した（`_SPEED_RECENT`・`_SPEED_SMOOTH`）。全部の
  観測の平均だと、相手の走り方が変わると古い周の値で外れた（標本外の外れの p90 が進む距離の 52%）
- **軌跡に覚える点を、見えている点の重心から後端（経路に沿って最も後ろ × 横の平均）にした**（`Slam2dRaceLine._opp_ref`）。
  重心は自車から見える面（後ろ面だけか側面までか）で 10〜20cm 動き、差分で覚えた速さが場面ごとに外れた。直すと標本外の外れの
  p90 が 0.27〜0.60 → 0.03〜0.05 になった（同じベンチ条件）。予測も相手の後ろ面（`Track.s_lo`）から進めるので揃う

## 5. 追い抜きの計画（`overtake.plan`）

ForzaETH の状態機械（GBFree / Trailing / Overtake）と Predictive Spliner の「追い付く区間を予測して、そこでだけ横へ出る」を、
既存の Frenet 格子に入れた。

- **区間の入口まで付いていく候補**（`Cand.S1`）: 道幅のある区間の入口まで線の上で付いていき、入口で横へ出て全速で抜く。
  ★今すぐ横へ出る候補だけだと、相手の後ろ 1〜2m から追い付くまでも横に出たまま走ることになり、その分長く道幅が要った
- **付いていく候補**は前の相手の予測の後ろを走る（`_follow_times`。出始めた後は加速度の上限で全速へ戻る）。
  付いていく車間は付いていく制御と同じ「止まり切れる車間＋空走」（`follow_keep`・`follow_react`）。今の車間が短ければ
  「今より近づかない」だけを求める
- **抜き切りが確かめられない試みは始めない**: 動く相手には戻り終える候補だけ。すぐ横へ出る候補（出始めが `_COMMIT_M` 以内）は
  見る先の終わりで相手の前に出ていることも求める。出始めがまだ先の候補は今は付いていくだけで、出る直前に確かめ直す
- **一度横へ出たら、有効な間は乗り続ける**（ForzaETH の Overtake 状態）。所要時間の小さな差で毎周期選び直すと、左右・遠近が
  入れ替わってどれにも乗り切れなかった
- 見る先は動く相手がいるとき 12m（`_H_OT`）
- 計算: 候補 約 2000 本、Mac で平均 3〜4ms（旧 約 400 本・0.8ms）

- ★2026-11-26 に直したこと:
  - **候補の時刻を、横ずれした道のり（`√((1−κr·d)² + d'²)` 倍、`_path_ds`）で出す**。以前は経路の弧長で出していて、カーブの
    外側を回る候補を短く（κ=0.45・外へ 0.4m で 18%）、内側を長く見積もっていた。順位付けでは、線より短い道のり（内側）は
    得にしない（速度の上限で抑えた所で内側へずれる候補が線より速くなり、障害物が見えるたびに線を外れたため）
  - **「今すでに車間の内側か」（付いていく候補を使えるか）を、制御が保つ車間（上乗せ前の `follow_keep`）で見る**（観測の揺れ
    0.05m は許す、`_INSIDE_TOL`）。上乗せ（予測の不確かさ × 遅れ・近づく速さ × 指令の遅れ）込みで見ていたので、制御どおりに
    付いていくほど常に内側に居ることになり、「区間の入口まで付いていってから抜く」候補が全部捨てられていた（HEAD からの不具合）
  - 道幅は格子の点の前後の区間（経路の細かい点）の最小で、曲率は格子の点の中点でも確かめる。乗っている計画を続ける候補だけは
    道幅 2cm・曲率 3% を許す（`_KEEP_ROOM_TOL`・`_KEEP_KAPPA_TOL`）。時間が最短の候補は道幅が尽きる直前で戻るので境目に居り、
    毎周期の格子のずれ（0.2〜0.3m）で同じ計画が通ったり落ちたりして「横へ出ては戻る」を繰り返した

## 6. 付いていく制御（`slam2d_raceline`）

- 付いていく車間は計画と同じ `_STOP_GAP`＋空走（"blocked" のときも。以前の `_FOLLOW_GAP` 0.7m は「横へ出られる距離を残す」
  ためで、今は計画が確かめる）
- **横へ出始めた後は車間の制御（`_acc`）を掛けない**（計画が時刻つきで確かめてある。車体のすぐ前の当たり判定は見続ける）
- "blocked" でも付いていく相手を返す（減速しきれない等で付いていく候補が落ちたとき、止まらずに付いていく）
- ★2026-11-26: 計画が付いていく相手を出していれば、"clear" でも "blocked" でもその相手・その車間（Frenet の後ろ面）で付いていく
  （`_acc`）。以前は "clear" では線の横 12cm 以内の点で相手を拾い（`_moving_ahead`）、判断が周期ごとに入れ替わるたびに測る
  車間が変わった。計画の相手が無いときだけ従来の `_moving_ahead`
- ★2026-11-26: 相手の速さは、計画が覚えた速さで予測した今の速さ（`OvertakeResult.lead_u`、付いていく計画と同じ遅い側）。
  追跡の生の速さがそれより 0.5m/s 以上遅いときは生の速さ（急に止まった相手・覚えたのと違う走り方。`_lead_speed`）。生の速さは
  一定の速さの相手でも 0.1 秒ごとに ±0.3〜0.5m/s 揺れる

## 7. 残っていること

- **車間を詰める（0.3m）には、付いていく制御の作り替えが要る**。試した結果（2026-11-21）: 相手 0.75 倍で抜けず、こちらから当てる
  接触が 1 本に 3 回（ヘアピンの入口とコーナー）。原因: 付いていく制御（`_acc`・`_moving_ahead`）は相手の点が自分の線の
  横 12cm 以内かで相手を拾う幾何の判定で、コーナーで相手が横にずれると見失う。また指令の遅れ（約 0.27s）を空走として
  見込まないと相手の減速に間に合わない（予測で減速を先取りしても減らなかった）。計画の時刻つきの当たり判定（相手の予測・
  不確かさ・自分の速度計画）で付いていく速さそのものを決める（計画の速度を指令にする）形にするのが筋
- 試す中で直した認識の誤り（車間を戻しても残す）: 姿勢は「今」へ進めるのに動く物は点群の時刻のままだった（前の車が約 0.2m
  近く見えた。`_advanced`）、残像の点が見えている後ろ面より手前に残っていた、付いていく候補の「減速しきれない」で候補を
  捨てていた（物理的に走れる速さで時刻を出し、当たり判定に任せる）、付いていく車間を今の車間に抑える計算の誤り
- **付いていく速さを計画の速度で決める作り替えを試した（2026-11-23、入れていない）**: 計画器が選んだ候補の速度を走る経路の
  速さの上限にし、幾何の車間制御をやめた。車間 0.3m でも、安全の決まりの車間（0.35m＋空走）でも、相手 0.55〜0.75 倍で 1 本に

# 前方ステレオ視の開発計画

後カメラを前へ移し、**左右対称・基線 75mm** のステレオ視にする計画。段階0（配置の切り替えと同期の土台）と段階1（取付後の確認）は
2026-11-12 に済んだ。段階2（ステレオ校正）も同日に済んだ。段階3 は道具（記録の組・ベンチ）まで、段階4 は `stereo_node` まで実装し、
どちらも実機での測定が残っている（照合の設定は仮）。**段階5 は方針だけ決めた（未実装）**。この文書がその手順書になる。

- 目的: LiDAR の走査面（路面から 0.095m）より低い障害物を見ること、およびステレオ視そのものの学習
- 電流の条件: 制御系の電流を、ステレオ中も 0.6A → 最大 1.1A 程度に収める
- 進み具合の正は [`../PROGRESS.md`](../PROGRESS.md)。数値の正は `config/vehicle.toml`

## 1. 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 配置 | 左右対称、基線 75mm（剛体の1枚の部品に固定） | 距離の誤差は基線に反比例する。取付の角度が動くと校正が崩れる |
| 主カメラ | **右**（libcamera 0 番、i2c@88000＝CAM0 ポート。前後配置で後ろに付いていた個体。2026-11-12 にケーブルを左右で入れ替えた） | バンビの指定 |
| 前方映像の表示 | 右カメラ1台（`image/front`）。**左右の映像は合成しない** | 7.5cm しか離れていないので遠くの視野はほぼ増えず、近い物が二重に写る |
| 模倣学習（`cam_e2e`）・E2E 融合（`e2e_fusion`）の入力 | **左右2台**（同期した組）。2026-11-13 に右1台から変更 | 右カメラは右下に右前輪横の床、左カメラは左下に左前輪横の床が写り、近くの縁（横位置の最も強い手がかり）が2台で別の情報になる。取付が左右対称なので「左右を入れ替えて鏡像」の反転も成り立つ。代わりに推論の計算がほぼ倍 |
| ステレオの距離の使い道 | 照合した距離（`scan/stereo`）は学習の入力に混ぜず、古典的な処理で障害物の点として planner に渡す | 原因を切り分けやすい。学習には生の左右2枚を入れる（上の行） |
| 既存の学習済みモデル | 使えなくなってよい（視点が変わるので録り直して再学習する） | バンビの判断 |
| 前後配置へ戻す道 | **無くした**（2026-11-13）。`layout` の切り替え・後カメラ・右1台の学習と推論の経路をコードから消した。戻すなら git の履歴から | 戻す可能性はかなり少ない（バンビ） |
| 自動運転画面の「後方」の枠 | 深度映像に置き換えた（段階4） | バンビの指定 |
| ラジコン画面のバックミラー・R での後方切り替え | 消した（11-13） | 後ろを見るカメラが無い |

## 2. カメラの対応と同期（段階0 で実装）

段階0 では `[sensors.camera] layout` で前後配置と切り替えられるようにしたが、2026-11-13 に前後配置をやめ、切り替えごと消した。

| リング | 共有メモリ | 役割・トピック | libcamera |
|---|---|---|---|
| 0 | `surge_cam0` | 右＝主カメラ `image/front` | 0 番 |
| 1 | `surge_cam1` | 左 `image/left` | 1 番 |

- 対応そのものは `raspi/core/vehicle.py` の `CAMERA_DEVICES`。**`image/front` は右の主カメラ**で、推論ノード・前方映像・📷・記録が読む
- 取付位置と校正値はレンズのプロファイルに持つ（プロファイル＝「モジュール＋レンズ＋取付」の組）。
  `[sensors.cam_front] lens = "wide160sr"`（右）と `[sensors.cam_left] lens = "wide160sl"`（左）
- `CamConfig.stereo`（telemetry_node → camera_node）が True の間だけ、左カメラを主カメラと同じ fps で回して同期する。
  False なら左カメラを止める。条件は `_desired_stereo`（照合する間・左右の組で推論するモードが ARM 中・左の映像を使う者がいる間）
- 同期は libcamera のソフト同期（`SyncMode`。主カメラが Server、左が Client）。揃ったコマは `ImageRef.synced` が True。
  **ステレオの照合は `synced` の組だけを使う**。`synced` は libcamera の `SyncReady` に加えて、もう1台の直近のコマとの
  差を camera_node が測り、0.5ms 以内（`STEREO_SYNC_TOL_NS`）のときだけ立てる（`SyncReady` は fps を変えた後も立ったままになる。§3）
- 左カメラの露光時間とゲインは主カメラの値を写す（`CameraWorker._follow_exposure`）。同期中の主カメラの AE は
  露光の短いプロファイル（`STEREO_AE_EXPOSURE_MODE = "Short"`）
- `hb/camera` の detail に `sync=ready / wait / off` が出る

## 3. 測定済みの値

| 項目 | 値 | 条件 |
|---|---|---|
| 同期なしのフレーム開始の差 | 起動のたびに 0〜16.7ms のどこか（実測の1例は 1.83ms、約 1.7µs/s でずれる） | 30fps |
| 同期ありの差（単体の試験） | 平均 ±23µs、95% が 35µs 以内、最大 79µs | 30fps・43 秒・標準チューニング |
| 同期ありの差（`camera_node` 経由・バス上） | 中央値 20µs、95% が 27µs、最大 67µs（`synced` の 145 組） | 10fps・`imx219_wide160.json` を重ねた状態 |
| 揃うまでの時間 | 30fps で約 3 秒、10fps で約 10 秒（libcamera の既定が「100 コマ後」） | — |
| 同期ありの差（取付後・バス上） | 14fps: 中央値 20µs・最大 73µs。30fps: 中央値 20〜47µs・最大 109µs（`synced` の組） | 640×480・`bottom_crop` 0 |
| 起動してから揃うまで | 30fps で 4.0 秒（2 回とも） | `camera_node` を起動し直して測った |
| fps を変えた後のずれ（`SyncReady` は立ったまま） | 最大 19ms。0.5ms 以内に戻るまで 14→30fps で約 15 秒、30→14fps で 35 秒以上 | 走らせたまま `FrameDurationLimits` を変える今の作り |
| 同じ場面で `synced` を測った差で決めた後 | `synced` の組の差は最大 0.34ms（0.5ms を超える組は 0）。14→30fps では 15 秒後から全コマが `synced` | 修正後 |
| 左カメラの電流の増分 | **+57mA**（右だけ 541mA → 左右 598mA。A-B-A-B、各 40 秒・σ5〜7mA） | DISARM・30fps・同期あり・640×480 |
| 露光の追従 | 主カメラの露光×ゲインを 13ms×2.0 〜 60ms×7.5 の間で 5 回動かし、左は 2 秒以内に同じ値（比 1.00〜1.01）になった | 主カメラの AE の目標（`ExposureValue`）を動かして試した（部屋が暗く、そのままでは上限に張り付くため） |
| 視聴者がいないとき | `front=off left=off sync=off`（左カメラが止まる） | DISARM |
| 2台の読み出し方向 | 同じ（撮像中のセンサー形式は2台とも `SBGGR10`、`Rotation` は2台とも 180） | — |
| 照合の計算時間（Mac M3・1 スレッド・OpenCV 5.0） | StereoBM 640×160・視差 96 で 2.5ms、StereoSGBM 同 7.6ms、SGBM 640×480 で 21.6ms | 合成画像 |
| 電流の換算 | 1 コア全開で約 110mA（`e2e_fusion` の実測 18.6ms×10Hz で +20mA から） | DISARM・1.5GHz |

距離は Z = f·B/d（f ≈ 308px @640 幅、B = 0.075m なら Z ≈ 23.1/d [m]）。誤差の目安（サブピクセル 0.25px）は
1m で ±1cm、2m で ±4.3cm、3m で ±10cm。解像度を半分にすると誤差は倍になるので、**横は 640 のまま縦だけ削る**。

**まだ確かめていないこと**
- Short プロファイルで露光が実際に短くなるか。夜の室内では 30fps で 33.3ms × ゲイン 9.85、14fps で 60ms × 7.5 と
  周期いっぱいまで延びた（暗いと Short でも延びる）。会場の明るさで主カメラの露光時間を見る
  （`camera_node` を `--quiet` なしで起動すると `cam0 synced 33.3ms×9.85` の形で出る）
- ~~ARM したときの揃い直し~~: 段階4 でステレオ中は前カメラの fps を ARM 中の値に固定した。11-13 に実際に ARM して、
  深度映像に繋いだまま ARM しても組が途切れないこと、ARM 中に繋いでも 3.5s で揃うことを確かめた（段階4 の表）。
  このときは駆動用バッテリーの電圧が足りず、モータドライバは起動していない（`armed` は立った）
- 露光: 夜の室内（11-13 0 時）では ARM の前後とも 33.3ms × ゲイン約 7 で、周期いっぱいだった。会場の明るさではまだ見ていない

## 4. 残りの段階

### 段階1: 取付後の確認
**2026-11-12 に完了。** 位置を実測して `layout = "stereo"` を Pi に反映した（ケーブルを左右で入れ替えたので
右 = libcamera 0 番）。確かめた結果（数値は §3）:

- 2台とも正立で同じ向き。左右の対応も正しい（同じ物が `image/front` では左寄りに写る＝右カメラ）
- 同期: `hb/camera` は `sync=ready`。差は最大 0.11ms。fps を変えた後は `SyncReady` が立ったまま最大 19ms ずれていたので、
  `synced` を測った差で決めるように直した（§2・§3）
- 映り込みと `bottom_crop`: **0 にした**（`wide160sr`・`wide160sl`。640×480 の全画角）。車体（天板・配線・前輪）が下半分の
  約6割に写るが、右カメラは右側、左カメラは左側の床が下端まで見える（車のすぐ横の線が写る）。学習系は車体が写ったまま使う。
  色・明るさで判定する古典処理（ライントレース・物体追従・矢印信号）は車体の配線に反応しうる（マスクは入れていない）。
  代償: 同じ行数のマスクが縦に 1.4 倍の範囲を受け持つので、低い解像度（160x120）では 2m の壁が 1.55m に出る
- 明るさ・色: 机の上で撮った1組では右が左より暗く紫がかっていた。床の上の組では差は目立たない。段階2 の校正の前にもう一度見る
- GUI（実機の画面を撮って確認）: ラジコン画面は右カメラの映像でミラーは出ない。自動運転画面の2台目の枠は「左」。

- 露光の追従・電流・fps を変えたときの揃い直しは測った（§3）。残りは §3 の「まだ確かめていないこと」の 2 点

### 段階2: ステレオ校正
**2026-11-12 に完了（合格）。** 手順は [`calibration.md` §7.2](calibration.md)、値は `vehicle.toml` の `[sensors.stereo]`。

| 項目 | 値 |
|---|---|
| 内部パラメータ | 右 `wide160sr` RMS 0.131px・左 `wide160sl` RMS 0.125px（各 13 枚）。fx は右 309.5・左 312.2 |
| ステレオ | 13 組、再投影誤差 0.369px |
| 基線 | 76.2mm（合格 75±2）。T = (−76.0, 0.9, −5.6) mm ＝ 左カメラが右より 5.6mm 後ろ |
| 左右の向きの差 | 1.69°（回転ベクトルで ロール 1.51°・ヨー −0.75°・ピッチ −0.12°） |
| 平行化後の縦ずれ | 中央値 0.29px（合格 0.5px 以下） |

- 左右のロールの差 1.5° は平行化で打ち消すので照合には効かない。前後 5.6mm のずれが実物どおりかは実測していない
  （z は基線の向きに直交するので、ボードの写り方によっては決まりにくい。段階3 で LiDAR と比べて距離が合えば問題ない）
- 再投影誤差 0.37px は単体（0.13px）より大きい。右と左の写真が数百 ms ずれて撮られるので、ボードがわずかに動いた組が混ざっている可能性がある
- 段階3 の前に Pi へ反映する必要は無い（`[sensors.stereo]` を読むノードがまだ無い）。反映は `tools/deploy.sh --restart`

実装の中身:

- `tools/cam_calib`: 📷 の右（`front`）と左（`left`）を名前の時刻で組にし（`pair_shots`、1.5 秒以内）、左右の内部パラメータ
  （既存の `calibrate`）を固定して `cv2.fisheye.stereoCalibrate` で R・T を求める（`stereo_calibrate`）。GUI はカメラの「ステレオ」、
  CLI は `--stereo`。合格のときだけ左右の `fisheye` と `[sensors.stereo]` を書く。カメラの選択肢に「左」も足した（左だけの内部パラメータ）
- `raspi/core/stereo_model.py`: `StereoCalib`（R・T・校正時のレンズ名）と `StereoRectifier`（平行化の表を起動時に numpy で作る。
  `cv2.fisheye.stereoRectify` は使わず `camera_model.py` と同じ式。原点は右＝主カメラ、仮想ピンホールは2台共通、`rows` で縦だけ削れる）
- `Vehicle.stereo`: stereo 配置で、校正時と今のレンズが同じときだけ入る
- **合否**: 平行化後の対応点の縦ずれの**中央値** 0.5px 以内（水平 100° の平行化画像に写る角点で測る）、基線の推定値 75 ± 2mm。
  計画では統計量を決めていなかった。95% 点は検出の外れ値に支配され、合成画像では真の値でも 0.69px になるので中央値にした（理由の数値は calibration.md §7.2）
- 合成画像（左右で別の内部パラメータ、0.6°・0.3°・0.4° の回転、基線 75.4mm）で: 基線の誤差 0.3mm、向きの誤差 0.15° 未満、縦ずれの中央値 0.11px。
  テストは `tools/cam_calib/tests/test_stereo.py`・`raspi/tests/test_stereo_model.py`

### 段階3: 記録と Mac でのベンチ
シムはカメラを描かないので、開発は実機の記録を Mac で再生して行う。
**道具は 2026-11-12 に実装済み（Pi へは未反映）。実機の記録ではまだ測っていない。**

- 記録（`raspi/nodes/logger_node.py` の `_pump_stereo`）: 右と左がどちらも `synced` の間は、2台の最新のうち古い方の撮影時刻に
  合わせ、両方のリングから 0.5ms 以内のコマを探して**同じ瞬間の組**で焼く（`FrameRing.find`・`RingJpeg.encode_at`）。
  組の JPEG 品質は `--stereo-jpeg-quality`（既定 90。ほかは 70 のまま）。同期していない間はこれまでどおりカメラごと。
  GUI の MCAP 記録・`tools/record.sh`・`surge-logger` のどれも `logger_node` なので全部に効く
- **記録に残すもの（2026-11-13、「同じ入力・同じ設定で照合をやり直せる」ため）**
  - `/viz/image/front`・`/viz/image/left`: 同じ瞬間の組の JPEG（上の `_pump_stereo`）。**撮る頻度は `--image-hz`**（`logger_node` 既定 5Hz、
    GUI の記録は `image_hz` 指定）。照合は 10Hz なので、照合の全組を残したいときは `--image-hz 10`（約 +10MB/分）
  - `/stereo/info`（`StereoInfo`、照合ごと）: 左右の撮影時刻の差 `dt_lr_ns`、遅れの内訳（`cam_ms`・`wait_ms`・`read_ms`・`proc_ms`・`latency_ms`）、
    障害物の点数 `n_points`、視差の出た割合 `valid_frac`、**その時の照合・抽出の設定**（`algo`・`scale`・`num_disp`・`block`・`rows`・`z_min`…`slice_m`）、
    右カメラの取付 `cam_pose`。`scan/stereo` と同じ `t_capture`・`seq` で突き合わせる
  - `/scan/stereo`: 方位ごとの距離（0 = 見つからない）。`/stereo/depth` は表示専用の損失画像（解析には使わない）
  - `/cam/config`: 照合（`depth`）・左右同期（`stereo`）を回していた期間。`/stereo/info` が無い区間が「回していなかった」のか「記録が欠けた」のかを分ける
  - `/vehicle_state`（`pitch`・速度・舵角）、`/scan`（LiDAR）、`/diag/link`（`stereo_ok`・`auto_stop_stereo`・`auto_stop_active`）: 誤検出の切り分けに使う
  - メタデータ `provenance`（`raspi/rec/provenance.py`）: **`vehicle_toml`（校正値の全文）**、`git`、`src_sha`（ステレオ関連ファイルのハッシュ。Pi は `.git` が無いので
    Mac のコードと突き合わせる用）、`protocol_version`
  - 読む側: `tools/stereo_bench/data.py` の `load_run_info()`・`load_stereo_info()`・`load_frames()`。`tomllib.loads(load_run_info(p)["provenance"]["vehicle_toml"])` で
    撮った時の校正値が取れる
  - **記録に無いもの**: 平行化・視差そのもの（画像と校正値から作り直せる。損失の JPEG でも `--requality` で差を確かめられる）、方位ごとの点の高さ・点数
    （C の後処理の内部。足すなら `stereo_native.c` と numpy 版の両方）。Pi が STM32 に送った `STEREO_OBS` は `scan/stereo` から
    `raspi/core/stereo_obs.py` で同じに作れる（`tools/fwsim/stereo_replay.py`）
- `tools/stereo_bench`（`python -m tools.stereo_bench REC.mcap`）: `StereoBM`/`StereoSGBM` × 640/320 幅（`PRESETS`）、
  `--rows` で照合する行、`--requality 70` で JPEG 品質の効き、`--save` で平行化した左と視差の絵。時間は既定 1 スレッド
- **物差しは LiDAR**: 走査面（`[sensors.lidar] z` = 0.095m）±2cm に入るステレオの点を 1° の方位ごとに中央値でまとめ、
  同じ方位の LiDAR と比べる（車速 0.05m/s 以下の組だけ）。そのために `Vehicle.lidar_z` を足した
- 物差しの確かめ（合成）: 左右の実際の校正値に近いレンズ・R・T で模様の壁を描いたテスト（`tools/stereo_bench/tests/`）で、
  LiDAR とステレオの偏りは 0.2% 以内。T を 1.1 倍に誤らせると偏り +9.5% として出る。縦の向きを 0.3° 誤らせると偏りは出ず、

### 段階5: 自動運転で使う
モードごとの扱い（2026-11-13 にバンビと決めた）:

| モード | 扱い | 理由 |
|---|---|---|
| カメラ模倣学習（`cam_e2e`） | 入力は**左右2台**（§1）。段階6 で録り直して再学習。車体のマスクは入れない。反転の水増しは「左右を入れ替えて鏡像」の形でだけ使う（車体の写り方が左右対称か確かめてから） | 1台を単に鏡像にすると、右下にだけ床が写る右カメラでは実機で起きない見え方になる（学習 GUI の既定は「反転しない」にした） |
| ライントレース（`line_trace`） | ステレオは使わない。`near_range` の手前側を車体が写る行より奥に張り直すだけ | 帯は地面の距離で決まり、カメラのずれも IPM（`ext.y`）が見ている。車体の白い配線は帯を奥へ置けば外れる |

| 対象追従（`follow_object`） | ① 方位の視差を直す ② 枠の中の距離をステレオでも測る | ① 今は方位をカメラの位置（x 0.09, y −0.0375）から出し、LiDAR を自分の原点からの同じ方位で引いている（1m 先で約 2° ずれる）。カメラの光線に最も近い LiDAR の点を選ぶ。② 枠は小さいので `cam_track_node` 自身が枠の中だけ照合する。LiDAR の走査面より低い対象も追える。2m より遠くはステレオの誤差が大きいので LiDAR を優先 |

| 経路選択走行（`slam2d_route`）・LiDAR だけの走行 | 変えない | — |

  左右を同期している間は、カメラ系の engage でも前カメラの fps を上限へ上げない
- 残り: Pi で2モデルの推論の遅れ・電流を `stereo_node` と同時に測る／左右の組で記録を録って学習する（段階6）

進める順: 対象追従の視差の修正（録り直し不要）→ `scan/stereo` の実地確認（段階4 の残り2）→ fps の固定 → `e2e_fusion` の安全の層 →
対象追従のステレオ距離 → ライントレースの帯の張り直し。再学習は段階6。

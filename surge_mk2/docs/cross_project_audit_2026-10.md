## 1. 結論

### 1.1 単位・スケール

**通信上の単位・スケール・エンディアン・CRC の食い違いは見つかりませんでした。** 「Nm で送って mNm で処理」に類する不一致はありません(突き合わせ表は 2 章)。車輪半径 0.030 m、ホイールベース 0.230 m、トレッド 0.155 m も Pi と STM32 で一致しています。

問題は単位ではなく、**「止める」の意味がレイヤごとに違う**点に集中しています。

## 3. 問題点と修正方針

### P0: 安全に直結

#### P0-1 「惰行」が送信停止で実装され、MD は 0.5 s 間直前のトルクを出し続ける ◎

- **現象**: STM32 の `Coast()` は `BldcMotor_Stop()` を呼ぶだけで、その中身は `tx_enabled = false`(`src/control/drive.c:103-111`、`lib/bldc_motor/bldc_motor.c:205-207`)。BLDC は受理済みの指令をメインループで毎周適用し続け(`src/app/app.c:437-441`)、0.5 s 無受信で初めて停止モードに入ります(`app.c:275-281`)。
- **影響**:
  - 停車判定(`drive.c:441-444`、目標・実車速とも 0.05 m/s 未満)で `Coast()` に入ると、減速中の負トルクが最大 0.5 s 残ります。車体利得は約 20 (m/s²)/(N·m) なので、0.05 N·m 残るだけで 0.5 m/s 相当の逆向き加速になり、後退 → PI 再開 → 再停止の振動が起こり得ます。
  - mode=DISARM かつ ARM ビットあり、またはステア未較正のときも同じ経路を通ります。
  - Pi の `tools/ctrl_tune` と STM32 の `host/` は STOP を即時トルク 0 として扱っている(○)ため、チューニング用モデルと実機が食い違います。
- **修正方針**: `Coast()` で `BldcMotor_SetTorqueNm(0)` を送り続ける。送信停止を停止手段として使うのをやめ、MD のタイムアウトは通信断の保険に限定する。モデル側は実装に合わせて直すより、実機側を「即時トルク 0」に揃える方が簡単です。

#### P0-2 Pi 側の通信断は制動にならず、駆動電源が切れて惰行する ◎

- **現象**: Pi の io_node は、GUI 指令の途絶(150 ms)・TELEMETRY 途絶(200 ms)・`--allow-arm` なしのとき、mode=0 / flags=0 の COMMAND を送り続けます(`raspi/nodes/io_node.py:546-551, 645-646`)。telemetry_node のデッドマンも `DriveCmd(mode=0)` です(`raspi/nodes/telemetry_node.py:2645`)。STM32 は ARM ビットで駆動電源を直接切り替えるため(`src/vehicle/vehicle.c:179-180`)、MD ごと電源が落ちます。
- **影響**: 走行中に Wi-Fi が切れると、制動せず惰行します。COMMAND 自体は届き続けるので、STM32 の「100 ms 途絶で最大制動」も働きません。
- **認識の違い**: STM32 は緊急停止について「電源を切ると MD が制動できず停止距離が伸びる」と明記し、電源を切らない設計にしています(`vehicle.c:275-277`)。Pi のコメントは DISARM を「安全な停止ハートビート」と呼んでおり、方針が逆です。
- **修正方針**: 2 段で直すのが安全です。
  1. Pi: 異常系は DISARM ではなく `arm=1, brake=1, brake_torque=0`(最大制動)を送り、停止(`stopped`)を確認してから DISARM に落とす。
  2. STM32: 走行中に ARM が落ちたら、車速が停車判定を下回るまで制動を続けてから電源を切る。Pi のバグに依存しない防御になります。

#### P0-3 BLDC の過電流ラッチが競合で無効化され、止める経路がない ◎

- **現象**: `BLDC_Enable` は `is_overcurrent` を確認した後で `enable = true` を書きます(`src/bldc/bldc.c:604-613`)。この間に 20 kHz 割り込みがトリップ(`bldc.c:159-176`)すると、`enable` が再び真になります。トリップ条件は `!svc.is_overcurrent` なので再発動しません(`bldc.c:217`)。メインループ側の `HandleOvercurrent` は `BLDC_Stop()` を呼ばず(`src/app/app.c:356-373`)、`HandleFaults` が真を返すと `continue` するため(`app.c:433`)、止める処理に到達しません。
- **影響**: 発生確率は低い(窓は数命令)ものの、起きると過電流ラッチ表示のまま駆動が続きます。この基板にはハードの過電流保護がないとコード自身が述べています(`bldc.c:214-215`)。
- **修正方針**: `HandleOvercurrent` の先頭で `BLDC_Stop()` を呼ぶ。加えて電流ループ側の判定を `!svc.enable || svc.is_overcurrent` にして、ラッチ中は必ず出力を切る。後者だけでも競合は無害になります。

#### P0-4 STM32 は MD の異常・通信断を制御に使っていない ◎

- **現象**: STM32 で MD の `IsDataValid` / `IsLimitSynced` / status を参照するのは、テレメトリ(`src/comm/telemetry.c:37`)、サイドブレーキ(`src/control/drive.c:136-137`)、舵角の読み出し(`src/control/steering.c:108`)だけです。走行制御は MD の状態を見ません。
- **影響**:
  - 片側の後輪 MD が過熱(60 ℃)・電圧異常(7〜15 V 外が 500 ms)・過電流で止まっても、反対側は駆動を続け、ヨーモーメントが出ます。車速 PI は不足分を補おうと健全側のトルクを上げます。
  - ステア MD が止まると舵が効かないまま走り続けます。
  - MD は異常中 LED 点滅の `HAL_Delay` で状態フレームが約 1 Hz に落ちるため(`BLDC src/app/app.c:314-326`)、上位が異常ビットを知るのも 0.6〜1.0 s 遅れます。
- **修正方針**: STM32 に「MD 健全性」の判定を足す。いずれかの MD が 100 ms 無応答、または異常ビットが立ったら、両後輪を制動モードに切り替え、`TELEMETRY.flags` に専用ビットを立てる。BLDC 側は異常中も状態フレームを 2 kHz で送り続ける(点滅をタイマ駆動にする)。

### P1: 動作不良・事故につながり得る

#### P1-1 ステア中心が未較正でも ARM 要求だけでステアが動く ◎

- **現象**: `ApplyFailsafe()` は中心の有効性を見ずに `Steering_SetRoadWheelAngleRad()` を呼びます(`src/vehicle/vehicle.c:316`)。未較正時の中心は 0.0 rad です(`src/control/steering.c:55-56`)。Pi 未接続の間は毎周期ここを通るので、ステア MD の送信が有効になります。その後 ARM ビットが立つと駆動電源が入り(`vehicle.c:180`)、位置 0 rad の指令がそのまま届きます。
- **影響**: Flash 未較正の個体で、ステアが任意の機械角へ 0.1 N·m で動きます。`vehicle.c:228-233` のコメントは「未較正の中心点に基づく指令も避けられる」と述べており、実装と食い違っています。
- **修正方針**: `Steering_SetAngleRad` の入口で `center_valid` を確認し、偽なら送信しない。あわせて駆動電源の投入条件にも `center_valid` を入れる。

#### P1-2 ARM 直後、MD の起動を待たずに車速 PI が回る △

- **現象**: ARM で駆動電源が入ってから MD が指令を受け付けるまで約 1 秒かかります(起動時の待ちと電流ゼロ点校正。`BLDC src/bldc/bldc.c:531-534`)。STM32 はこの間も車速 PI を回します。
- **影響**: ARM と同時に速度指令があると、PI が飽和(±0.30 N·m)した状態で MD が応答し始め、最大トルクが一気に出る可能性があります。
- **修正方針**: 3 台の MD がそろって `LIMIT_SYNCED` になるまで `armed` を真にしない。MD 側は起動完了を status のビットで返すと確実です。

#### P1-3 プロトコル版などの不一致を Pi が表示するだけで走行を止めない ◎(版の照合)/ ○(ほか)

- **現象**: 起動時の `protocol_version` 照合は print だけです(`raspi/nodes/io_node.py:998-1000`)。`steer_center_valid` と制御パラメータの同期状態も ARM の条件になっていません(○)。
- **影響**: v0.18 で舵角の意味が「モータ角×0.5」から「実路面舵角」に変わりました。片側だけ入れ替えると最大約 2.4° ずれます(STM32 の CLAUDE.md も「上位と必ず一緒に入れ替える」と注意しています)。
- **修正方針**: 版が不一致、または `[control]` の同期が完了していない間は `allow_arm` を偽にする。

#### P1-4 BLDC が異常から復帰したとき、古い指令で再始動し得る ◎

- **現象**: 過熱・電圧異常の間は `RecvSerial()` が呼ばれず(`src/app/app.c:433`)、復帰時に受信バッファを破棄しません(過電流側だけ `app.c:370` で破棄)。`active_command` と制限値も消えません。タイマは 72 MHz の 32 bit カウンタで 59.65 s で一周するため(`lib/timer/timer.h:30-32`)、異常が長いとタイムアウト判定をすり抜けることがあります。
- **影響**: STM32 が送信を止めていた場合(P0-1 の惰行中)、復帰した MD が止める直前の指令で最大 0.5 s 駆動します。
- **修正方針**: `LatchFault` の復帰時に `EnterStopMode()` と `Serial_Reset()` を呼び、新しいフレームを受けるまで動かさない。

#### P1-5 自律走行のフェイルセーフが弱い制動・直進復帰になる ◎

- **現象**: planner の指令が古いとき、telemetry_node は `brake=True, target_steer=0.0` に差し替えますが、`brake_torque` は GUI の値のままです(`raspi/nodes/telemetry_node.py:2673-2676`)。
- **影響**: GUI のスライダを弱くしたまま自律走行すると、planner 停止時の制動も弱くなります。舵を 0 に戻す点は、STM32 の「途絶時は舵角を保持する。直進へ戻すと予期しない方向へ動く」(`vehicle.c:300`)と方針が逆です。
- **修正方針**: stale 時は `brake_torque=0.0`(最大)を明示し、`target_steer` は直前の値を保持する。

#### P1-6 IMU の復旧処理が約 190 ms メインループを止める ◎(既知)

- **現象**: IMU のサンプルが途絶えると `Recover()` がブロッキングで走ります(`src/sensing/imu.c:374-380`)。`src/app/app.c:254-263` に既知の問題として書かれています。
- **影響**: この間 MD への指令が更新されず、COMMAND の 100 ms タイムアウトも超えます。走行中に IMU の配線が接触不良を起こすと、500 ms ごとに 190 ms の制御停止が繰り返されます。
- **修正方針**: `Recover()` をステートマシン化して 1 周期 1 ステップにする。

**軽微なバグ・改善点(いずれも ○)**

- STM32: 前輪エンコーダ換算で 4095 と 4096 が混在。
- STM32: ブレーキ灯の減光タイマが約 23.9 s で折り返し、停車保持中に周期的に全光量へ戻る。
- STM32: CONFIG_ACK の送信キュー(256 バイト)が、接続時の連続 CONFIG_SET で溢れ得る。Pi 側は再送するので実害は小さい。
- STM32: MD 状態フレームは CRC-8 のみで、同期ずれ時に約 1/256 で誤受理する。ステア中心の較正は最初の 1 フレームだけで決めている。
- STM32: 超音波は DISARM 中に更新されず、古い値が有効値として残る。
- STM32: `printf` がブロッキング送信で、フォールト時に制御ループが最大 10 ms 止まる。
- BLDC: ウォッチドッグがなく、HardFault 時に PWM が最後の duty を出し続ける。
- BLDC: エンコーダ未校正でも既定値で通常運転に入り、上位は検知できない。
- BLDC: 校正用スイッチ入力(PA12)に内部プルがなく、外付けがなければ起動時に校正が走り得る。
- BLDC: 速度モード開始時にランプと積分を現在値で初期化しない(現状は未使用のモード)。
- Pi: io_node のメインループがシリアル例外を捕捉しない。落ちるとハートビートが止まり緊急停止がラッチする(安全側だが現地復旧が必要)。
- Pi: 時刻同期が回帰へ切り替わるまでの 15 秒は固定オフセットで、最大約 50 ms ずれ得る。
- Pi: GUI トグルの CONFIG_SET に再送・ACK 照合がない。
- 各所: コメントの周期表記(50 Hz / 1 kHz など)が実装と違う。

**調査の過程で否定した指摘**

- 「位置指令 [0, 2π) を MD が多回転で解釈する」: BLDC は偏差を ±π に畳むので発生しません(◎)。
- 「BLDC を再校正すると機械角のゼロ点が 2π/7 単位でずれる」: 電気角オフセットは 7 点すべての平均で、開始位置によらず同じ集合になるため、この形のずれは起きないと判断しました(`src/bldc/bldc_calibration.c:527-558`、◎)。ただし再校正でエンコーダの min/max と盲点幅が変わると角度のスケールがわずかに変わるので、MD を再校正したらステア中心も較正し直す運用を勧めます。

## 5. 未確認事項

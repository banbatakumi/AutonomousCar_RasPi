# 車両の校正（calibration）— 設計と手順

## 1. 方針

1. **slam2d の走行に要る値だけを測る。** 使われない値（シムの車の細かい癖）は測らない。
   シムが使う値は `config/vehicle.toml` の `[sim]` に置き、「実機の制御は読まない・同定しない」と明記する
2. **1つの校正は「測る → 決める → 確かめる」の3段。**
   - 測る（同定試験）: 開ループで車体の性質を測る。モデルは物理の式で、パラメータは少なく
   - 決める（設計）: 制御のゲインは**式**で決める（数値最適化の箱にしない）。式の前提も書く。式の前提が実機で成り立たない TC・ABS は、
    式で基準を作って**実機で振って**決める（校正 8）
   - 確かめる（検証試験）: **閉ループで制御そのものの効きを測り、合否を出す**。モデルが合って
     いるかではなく、制御が狙いどおりに効いているかを実機で直接見る
3. **解析そのものも確かめる。** 各解析は「真値の分かっているシムで試験を走らせ、解析が真値を
   復元するか」をテストに持つ（`tools/calib/tests`）
4. 記録はすべて TELEMETRY（100Hz）と指令。新しい計測手段は足さない

## 2. 校正の一覧と順番

| 順 | 校正 | 試験（planner） | 置き方 | 決まる値（書き込み先） |
|---|---|---|---|---|
| 1 | エンコーダ | `calib_encoder` | 直線 2m | 前輪エンコーダの出力の範囲・1回転の周期誤差（`[control] enc_*`） |
| 2 | ステア（静特性） | `calib_steer` | 約 1.2m 四方 | 舵のリンクの換算・中立のずれ・サーボの定常ゲイン（`[control] steer_link_*`、`[dynamics] steer_offset_rad`・`steer_servo_gain`、`max_steer`） |
| 3 | ステア（動特性） | `calib_steer_dyn` | 直線 2m | 舵のむだ時間・遅れ・ヨーの遅れ（`[dynamics] dead_time_s`・`tau_steer_s`・`yaw_*`） |
| 4 | 遅延 | `calib_latency` | その場 | スキャン完了→STM32 受理（`[dynamics] control_latency_s`） |
| 5 | 車速制御 | 測る `calib_speed`／確かめる `calib_speed_check` | 直線 2m | 車体の利得・転がり抵抗・トルクの遅れ → PI と FF（`[dynamics] speed_*`・`rolling_resistance`、`[control] speed_ff_*`・`launch_exit_torque_nm`） |

| 8 | TC・ABS のゲイン | `calib_tc_gain` | 直線 2m | 交差周波数を低い方から上げて発進・制動を実走し、発振の手前の kp・ki（`[control] tc_kp_nm_per_m_s`・`tc_ki_nm_per_m`・`abs_kp_nm_per_m_s`・`abs_ki_nm_per_m`）。P と I の比も比べる |
| 9 | TC・ABS の確かめ | `calib_traction_check` | 直線 2m | 実際に出る加速度・減速度（`[limits]`）と、TC・ABS の効きの合否 |

### 録る順番と、適用する段階

**1 を録ったら、ほかを録る前に必ず適用して `./tools/deploy.sh --restart-io`** する（GUI の「制御パラメータ: 適用済み ✓」を
確かめる）。ほかの試験の車速・走行距離・スリップ率はすべて、**録ったときに STM32 に入っていたエンコーダの校正**の上に乗る。

| 段階 | 録る | その後 Mac で |
|---|---|---|
| ① | 1 | 解析 → 適用 → `--restart-io` |
| ② | 2 → 3 → 4 → 5（測る）→ 7 → 6（台に載せる）。間で適用しなくてよい（どれも録る前に要る値は 1 だけ） | 2・3・4・5・6 を解析・適用 → 7 を解析・適用（7 の解析は 5・6 の値を使う）→ `--restart-io` |
| ③ | 8（7 の目標を `--restart-io` で STM32 に入れてから録る） | 解析 → 適用 → `--restart-io` |
| ④ | 5（確かめる）→ 9 | 解析。9 の `[limits]` を適用 |

8 は 5・6（J と MD の遅れでゲインの基準を作る）と 7（目標スリップ率）を、9 と 5（確かめる）は 5（測る）・7・8 を、STM32 に入れてから録る
（確かめの試験は**STM32 に入っている値の効き**を測る）。

**解析が録った条件を確かめる**: 2〜9 の解析は、記録の `/diag/link`（録ったときに STM32 に入っていた値）を今の
`vehicle.toml` と突き合わせ、エンコーダの校正（確かめの 2 本はそのゲインも、8 は目標スリップ率も）が違えば★を出す（`tools/calib/__init__.py` の
`prereq_check`）。★が出たら、適用して `--restart-io` してから録り直す。

## 3. 測らないもの

加速・減速の上限は 9 で**実測**（TC・ABS を入れた状態で実際に出る値）、横の上限は 7 のタイヤの μ から見積もる（摩擦円の仮定。走行中の学習 `grip_learn` が初期値から上げ下げする）。
サーボのヒステリシス・リンクのガタ・制動トルク→減速度など slam2d が使わない値は測らない（シム専用 `[sim]`）。

**MD（モータドライバ）を校正し直したら、トルク指令あたりの電流が変わるので校正 5 以降を録り直す**（それより前の記録の G・トルクの値は今の車に使えない）。

## 4. 各校正の中身

### 4.1 エンコーダ（`calib_encoder` → `tools/calib/encoder.py`）

前輪のアナログ絶対角エンコーダ（AS5600）の読み u（ADC÷フルスケール、0〜1）を STM32 が
`lib/encoder_cal` の式で真の角度へ直す:

    θm = (u − lo)/(hi − lo)·2π,   θm = θ + e(θ),   e(θ) = h1s·sinθ + h1c·cosθ + h2s·sin2θ + h2c·cos2θ

**測り方**: 直線でトルク 0 の惰行をさせる。惰行中の車輪の真の回転 θ(t) は転がり抵抗だけで滑らかに
減速するので、**時間の低次多項式**で書ける。読み（TELEMETRY の `front_angle`＝校正前の生の角度）は
θ(t) + e(θ(t)) なので、1 区間ごとの多項式と、全区間で共通の (lo, hi, h1s…h2c) を同時に最小二乗で
当てはめる。惰行 1 回で車輪は数回転するので、角度の関数（周期誤差）と時間の関数（減速）は分かれる。

- なぜ惰行か: 速度制御中は PI が周期誤差を含む車速に合わせてトルクを揺らし、真の回転にも同じ周期の
  うねりが乗る（誤差を小さく見せる）。惰行中は何も読み返さない
- **確かめ方**: 校正を入れた後にもう一度録り、STM32 が出す校正後の走行距離 `odom_dist` に同じ当てはめを
  すると、周期誤差の振幅が測定ノイズ程度まで落ちる（落ちなければ不合格）。速さの違う 2 段の惰行で
  係数が一致することも見る（一致しなければ角度の関数でない誤差＝振動などが混ざっている）

### 4.2 ステア（静特性）（`calib_steer` → `tools/calib/steer.py`）

slam2d は「狙う曲率 → 送る舵角」の換算（`Vehicle.steer_map`）を使う。舵のリンクは線形ではなく、
STM32 がモータ角 x（×リンク比 0.5）を路面舵角 δ = g·x + c·x³ に換算している（`[control] steer_link_*`）。

**測り方**: 低速（0.45m/s）で舵角を固定して弧を走り（前進し、同じ舵のまま後退して元の点へ戻る）、
舵角の段を −最大〜＋最大で振る。低速なのでタイヤの横滑りは無視でき、運動学の関係

    曲率 κ = ヨーレート ÷ 車速 = tan(δ_実) / L

から実際の舵角 δ_実 = atan(κL) が出る。各段で (モータ角 x, δ_実) の組を集め、
δ_実 = g·x + c·x³ + δ0 を当てはめる。δ0 が中立のずれ（`steer_offset_rad`、Pi 側で引く）。
サーボの定常ゲイン `steer_servo_gain` は報告舵角 ÷ 指令舵角（保持中の平均）。
記録時に STM32 に入っていた換算は `/diag/link` から読んで x を戻す（換算を入れ替えても測り直せる）。

- 前進と後退で同じ弧をたどるので、置いた場所から大きく動かない
- **確かめ方**: 入れた後に録り直すと g=1・c=0・δ0≈0 に戻る（残差が段ごとの曲率のばらつき程度）

### 4.3 ステア（動特性）（`calib_steer_dyn` → `tools/calib/steer.py`）

slam2d は「舵を送ってから曲率が付くまでの遅れ」（`Vehicle.steer_delay_s` = むだ時間＋サーボの
1次遅れ＋ヨーの遅れ）を先読みに使う。

**測り方**: 直線を 1.0m/s で走りながら舵を小さく（±6°）方形波で振る。
- サーボ: STM32 がランプさせた参照舵角 `steer_cmd_echo` → 実舵角 `steer_actual` に「むだ時間＋1次遅れ」
- ヨー: 実舵角から出る曲率（4.2 の換算）→ 実際の曲率（ヨーレート÷車速）に2次遅れ（ωn, ζ）

### 4.4 遅延（`calib_latency` → `tools/calib/latency.py`）

止まったまま、スキャンが来るたびに舵の指令の符号を反転し、舵角にスキャンの番号を刻む
（`±(振幅 + 0.002rad×(seq mod 8))`）。スキャンの最後のセクタの受信時刻から、STM32 の
`steer_cmd_echo` がその値になった時刻までが遅れ。

### 4.5 車速制御（`calib_speed`・`calib_speed_check` → `tools/calib/speed.py`）

**車体のモデル**（後輪 2 輪の合計トルク T → 車速 v）:

    T_eff' = (T(t − d) − T_eff)/τ,   v' = G·T_eff − r_±   （r は前進・後退で別）

G は利得（名目 1/(車輪半径×質量) = 16.7 (m/s²)/(N·m)）、r は転がり抵抗の減速度、d・τ は MD の
トルクの遅れ。

**測る**（`calib_speed`、トルク直接指令。PI を通さない）: 前進・後退でトルクの段（加速→小さいトルク→
惰行 0）を掛ける。滑らない強さ（加速度 1.5m/s² 以下）に抑える。走行距離（微分しない）に出力誤差法で
当てはめる。

**決める**（2自由度制御。STM32 の構造はそのまま）:
- FF: `speed_ff_nm_per_m_s2` = 1/G（目標の加速度を出すトルク）、`speed_ff_rr_nm` = r/G（転がり抵抗を打ち消す）
- PI: 一巡伝達 L(s) = G·(kp·s + ki)/s²·e^(−s·Td)（Td = d + τ + 車速の推定の遅れ + 制御周期の半分）。
  交差角周波数 ωc と PI の零点 ωz = ki/kp を、**位相余裕**（既定 60°）から決める:
  位相余裕 ≈ atan(ωc/ωz) − ωc·Td。ωz = ωc/4 と置くと ωc = (76° − 60°)/Td。kp = ωc/G·cos(atan(ωz/ωc))、ki = kp·ωz
- 上限: ωc は `WC_MAX`（`tools/calib/speed.py`。車速の推定の雑音がトルクに出る大きさで決める）を超えない

**確かめる**（`calib_speed_check`、車速指令。ふだんの走りと同じ経路）: 加速のランプ・定速・減速の
ランプ・段の指令を前進・後退で出し、**実測の追従誤差を、同定したモデル＋決めたゲインのシムの予測と
比べる**。合否: ランプ中の追従誤差・行き過ぎが予測の範囲内で、振動が無いこと。

### 4.6 後輪の空転（`calib_wheel` → `tools/calib/wheel.py`）

後輪を浮かせ、小さいトルクの段で回しては止める。路面の力が無いので J·ω' = T_eff − T_f·sgn(ω) − b·ω から
車輪の慣性 J・摩擦 T_f・粘性 b、MD の遅れ（d, τ）が出る。TC・ABS の設計の材料（車輪の慣性が小さいほど
スリップは速く動く）。

### 4.7 タイヤ（`calib_tyre` → `tools/calib/tyre.py`）

**測り方**: TC・ABS・TV を切り（`fw_overrides`。片輪浮き対策の周速 7.5m/s の歯止めは残す）、直線で
トルクを**ゆっくり** 0 から最大（0.15N·m）まで上げる（`dramp`＝駆動 0.5〜1 秒・`bramp`＝制動 0.4〜0.5 秒、各 3 回。
手前の `trim` で定速のスリップ率の偏りを読む）。ランプなら制御器に依らず、低いスリップ率から山の先まで 1 本で測れる（低いスリップ率ではタイヤが硬く、スリップは
力にすぐ追従するので、0.5 秒程度のランプで準静的）。

- スリップ率: STM32 が制御に使っている値（`tc_slip`）の左右別から、`trim` の中央値（前輪の倍率誤差による 0.006〜0.011 の偏り）
  を引く
- 前後力の合計: 車体の加速度から F = m·(a + r_±)（校正 5 の質量・転がり抵抗。車輪の慣性を使わない）
- **駆動**: 各輪の力は車輪の運動方程式 (T − J·ω̇ − T_f)/r（T は各輪のトルク指令。J・T_f は 6）で左右別に出し、各輪の曲線を別々に
  当てはめる。車輪から出した左右の和が車体の合計と合うこと（0.85〜1.15）を確かめる。**目標は弱い輪の肩に合わせる**
  （TC は各輪が同じ目標を使うので、弱い輪の肩まで滑らせないとその輪の力が 95% に届かない）
- **制動**: MD の制動は低い周速でトルクが抜ける（指令と実際が違う）ので車輪から力を出さない。ABS は左右のうち滑りやすい方に
  合わせる（select-low）ので、車体の合計の力を**滑りやすい方のスリップ率**に対して当てはめる（ABS が実際に見る関係）。曲線の形が
  決まらない（係数が下限に張り付く。弱い輪が先に飽和して合計の力が二段に増える左右差の大きい車など）ときは駆動の目標を使う
- 形は F = D·sin(C·atan(B·λ))。λ は真のスリップ率 = STM32 の読み + a·L/v（読みの遅れ L は、低いスリップ率まで測れているので
  「力 0 でスリップ 0」を通すように決まる。基準速度の遅れなどもまとめた見かけの値）

**決める**:
- 目標スリップ率（`tc_slip_target`・`abs_slip_target`）: **ピーク付近 = 力が頭打ちになる点**（文献どおり。乾いたタイヤのピークは 6〜20%、
  Formula Student の 4WD で約 18%）。**測定したスリップ率のまま**（STM32 が TC・ABS に使う値。読みの遅れの補正をしない）、真のスリップ率の順に
  点を同じ数ずつの群に分けた力の中央値が、最大の 95% に届く最小のスリップ率（`empirical_peak`）。上限 0.3（`_TARGET_CAP`。それより先は
  横力をほぼ失う）。TC は各輪が同じ目標を使うので**左右の平均**（バンビ提案。大きい方に合わせると強い輪の保護が緩く、小さい方に合わせると弱い輪の力を削る。
  力は肩の付近でほぼ平ら）、ABS は滑りやすい方。実機の例: TC は左 0.15・右 0.31（右輪が左の数倍滑る）→ 0.23、ABS は 0.12〜0.20。
  - 山（その先で力が落ちる点）が見えないとき（実機はこちら）も、95% に届く点で頭打ちとみなして★。山がもっと先なら力を少し捨てている
  - 遅れの補正（真のスリップ率 = 読み + |a|·L/v）をした版は目標が 0.08〜0.1 に出て、TC に保たせると加速が 2.9→2.2m/s² に落ちた
    （右輪は力の 95% に届くのに 0.13〜0.25 の読みが要る）。測定値の knee が実際の発進に合う
  - 検討して外した案: 「最大トルクを一気に掛けたときのスリップ率」（TC 0.2〜0.35・右輪 0.65、ABS 0.6。それより下では何もしないのでピーク付近ではなく、
    横力をほぼ失う）。横に残る余力と前後の力を等しくする（約 0.10。直線の加減速が約 7 割）は、直線の試験では横力を測れていないので保留
  - **横グリップへの影響は直線の試験では測れていない**。コーナー立ち上がりで膨らむ場合は目標を下げるか、横加速度に応じて変える（ファームの変更）
  - 曲がっている所は slam2d のライン（`raspi/nav/raceline.py` の摩擦円）が前後の加速度を絞るので、TC・ABS が働くのは主に直線の発進・制動
- **ゲインは校正 7 では決めない**。スリップ速度 u = rω − v は、トルクに対してほぼ積分器 (r/J)/s で、その先に MD の遅れが
  ある。位相余裕の式でゲインを決めたら実機で高すぎて振動し、TC・ABS を切ったランプでも制動側の周速はトルクを掛けると
  揺れる（0.03m/s。定速は 0.004）ので、揺れの一部は制御器の外（MD・タイヤ）にあり、式の前提（滑らかなプラント）が成り立たない。
  ゲインは校正 8（§4.8）が実機の閉ループで決める
- **スリップ率の読みの遅れ L**: 駆動の各輪の曲線で決める（中央値。実機 63ms・シム 30〜70ms）。制動の曲線は L が B・C と入れ替わって
  決まらない（探索範囲の上限に張り付く）ので、制動は駆動の L に固定する。校正 6 の MD の遅れの合計（16ms）より大きいのは、
  基準速度の遅れなどを含む見かけの値。**TC・ABS が見るスリップ率はこの分だけ力より遅れる**
- **曲線が標準の式に合わないとき**（係数 C・B が探索範囲の端に張り付く。実機では右の駆動と制動）は、形を仮定せず、
  真のスリップ率の順に点を同じ数ずつの群に分けた力の中央値から、最大の 95% に届く最小のスリップ率を目標にする（`empirical_peak`。
  完全に滑った先（真のスリップ率 0.5 超）は含めない）。このとき μ・タイヤの係数・横の上限は書かない
- 横の上限の見積もり（`[limits] a_lat_m_s2`）: μ·g（前後と横の μ が同じ・前後輪の荷重の分担が横力の分担と同じ、を仮定。
  走行中の学習の初期値なので粗くてよい）。山が測った範囲に無いときは書かない

**合否・★**: ランプの間に TC・ABS が働いていたら不合格（切る上書きが STM32 に入っていない）。曲線の点が 12 個未満、スリップ率が
0.15 まで上がっていない（山の先が見えない）、最も低いスリップ率が 0.03 より大きい（肩が見えない）、左右の力の上限の比が
0.8〜1.25 を外れる（弱い輪の荷重・タイヤ・MD を確かめる）、同じトルクで左右のスリップ率が 1.5 倍以上違う、は★。

**決めた値は、ホストでコンパイルしたファーム＋同定した車輪・タイヤのモデル（`host/host_sim.c`）で発進・制動を回して確かめる**
（設計の式が前提を外していないか）。解析は真値の分かるシムのタイヤで目標が肩に出ること・左が弱い車で左が報告されることを
`tools/calib/tests/test_traction.py` で確かめている。

### 4.8 TC・ABS のゲイン（`calib_tc_gain` → `tools/calib/tc_gain.py`）

**ゲインを設計せず、交差周波数 ωc を実機で振って決める。** 基準のゲインは物理から作る（`vehicle.toml` の今のゲインは使わない。
それが壊れた値かもしれないので）。**試験の間だけ目標スリップ率を働く値（TC 0.09・ABS 0.18、`TEST_TARGETS`）に上書きする**（校正 7 の目標が
「最大トルクまで滑らせる」値だと制御器が働かず、ゲインを測れないため）。スリップ速度がトルクに対してほぼ積分器 (r/J)/s なので、交差周波数 ωc を決めれば kp が決まる:

    kp = ωc·J/r,   ki = kp·ωc/ratio       （PI の零点を交差の 1/ratio に置く。ratio = 4 が基準）

J は校正 6 の後輪の慣性、r = 0.030m。現行の kp 0.097 は ωc ≈ 80rad/s に当たる。

**P と I の比（ratio）の決め方**: 零点を交差の 1/4 に置くのは、積分が交差の位相を削る量を約 14° に抑える慣用の値で、実機で確かめた
根拠ではない。I を強く（ratio を小さく）すると目標への収束は速いが位相を削って振動しやすく、弱くすると行き過ぎが残る。
そこで 2 段で決める。

1. **ωc の梯子**: ωc = 15・30・60・120・240rad/s（比 4）で、全開の発進（TC）と最大の制動（ABS）を実走する。**発振**（区間内の
   スリップ率の揺れが 0.04 超で、一つの周波数に 50% 以上集まり、その周波数が 12Hz 以上、かつ**高周波の揺れが手前の片道の最小の 1.6 倍超**。
   12Hz 未満の遅い揺れはゲインが低くて目標に保てていないだけ。**実機は TC・ABS のゲインによらず 20〜30Hz の揺れが常にある**（TC・ABS を
   切ったランプでも制動側は 0.03m/s）ので、「一つの周波数に集まる」だけでは発振と言えない）を片道ごとに見張り、見つけた側は**それ以降の片道で発振したゲインへ戻らない**（最後に良かった値で走る。
   もう一方は上げ続ける）。TC と ABS は別々に進む
2. **比の掃引**: 採る ωc の側で、比を 2.5・8 に変えた片道（比 4 は梯子の片道）

**採り方**（解析）: **ゲイン余裕 2 倍**として、採る ωc は梯子で最初に発振した ωc の半分以下（発振が出なければ梯子の最大の半分以下）。
その範囲の片道（**比を変えた片道も含む**。I を強くすると低い ωc でも目標に保てることがある）のうち、発振せず平均スリップ率が
目標（校正 7）の ±0.04 以内のものから、加速度・減速度が最良の 95% 以上を保つ最大の ωc（高すぎるとトルクが暴れて性能が落ちる）を
採り、同じ ωc の中では始まりの行き過ぎ（スリップ率が目標の 2 倍を超えた時間）が最も短い比を採る。範囲に目標に保てた片道が無ければ
不合格（ゲインを上げると発振し、下げると保てない。校正 7 の目標を下げるか、路面・タイヤ・MD を確かめる）。書き込む値は
`tc_kp/ki`・`abs_kp/ki`。

「手前の片道の最小の 1.6 倍超」の条件は、実機で ωc を上げても高周波の揺れがほとんど増えない（＝発振ではなくタイヤ・MD の常在の揺れ）ことから
入れた。タイヤの傾きが急（スリップの極 a が大きい）と、積分器とみなした ωc より実際の一巡のゲインは低く（kp·(r/J)/a < 1）、不安定になりにくい。

制約: 記録の `/diag/link` に入っているのは基準の値で、片道ごとの上書きは指令の `fw_overrides` に残る（解析はそこから読み戻す）。
試験が途切れれば上書きは外れて toml の値に戻る。約 60 秒・直線 2m＋車長。

### 4.9 TC・ABS の確かめ（`calib_traction_check` → `tools/calib/traction.py`）

TC・ABS を入れたまま、直線で全開の発進と最大の制動を 3 回ずつ。

- 合否: スリップ率の平均が目標の ±0.05 以内、ばらつき（標準偏差）が 0.05 以下、振動（トルク上限の
  上下）が続かない
- **実際に出た加速度・減速度の中央値を `[limits] a_accel_m_s2`・`a_brake_m_s2` に書く**（走行中の
  学習の初期値・学習しないときの上限。slam2d は `FIXED_*_USE` の割合を掛けて使う。減速は車速指令で測る——
  slam2d の減速はこの経路）。予測（4.7 のモデル）と食い違えば★
- ★ 車速指令の減速（前進中に車速 PI が減速トルクを出す間）は TC ではなく **ABS が抑える**
  （STM32 `drive.c` の `ApplySpeedPiAbs`。TC が掛かると上限が 0↔0.15N·m を往復して後輪が滑りスピンする）。
  合否の目標スリップ率は ABS の値（select-low）

## 7. カメラ（魚眼レンズ）

前方ステレオの左右2台は IMX219 **160° 広角**。内部パラメータをチェッカーボードで校正して `config/vehicle.toml` に置く。
**校正値が無いカメラは `hfov` ピンホールで近似する**——160° では端ほど大きくズレるので、レンズを替えたら必ずやる。

**レンズで変わる値はプロファイルに分けてある**（`raspi/core/vehicle.py` の `resolve_lens`。キーの意味は `vehicle.toml` のコメント）:

```toml
[sensors.cam_front]
lens = "wide160sr"             # ← 付いているレンズ＋取付（右・主カメラ）

[sensors.cam_front.lenses.wide160sr]          # x y z roll pitch yaw（取付位置・姿勢）・hfov・bottom_crop・undistort_hfov
[sensors.cam_front.lenses.wide160sr.fisheye]  # 校正値（tools/cam_calib が書く）

[sensors.cam_left]
lens = "wide160sl"             # 左カメラ（項目は同じ）
```

- **取付位置・姿勢もプロファイルに持つ**（モジュールを替えるとステーも変わるため）。`z` は路面からレンズ中心まで、`pitch` は下向きが正
- **切り替えるとき**: `lens` を書き換えて `tools/deploy.sh --restart`。プロファイルを替えたらステレオ校正（§7.2）もやり直す（`[sensors.stereo]` は校正時のレンズ名と違うと使われない）
- **別のレンズを足すとき**: `[sensors.cam_*.lenses.<名前>]` を足す（名前は英数字と `-`。📷 のファイル名に入るので `_` は使えない）。
  存在しない名前を `lens` に書くと `config/generate.py`（CI の `--check`）が落ちる

| 使うところ | 校正値の効き方 |
|---|---|
| IPM（`raspi/nav/ipm.py`）→ `line_trace`・`ftg_cam`・`cam_centerline` | 画素 → 地面座標の変換が魚眼モデルになる |
| `cam_track_node`（`follow_object`）| 画素 → 方位角 |
| GUI の進路ガイド・重畳（`gui/src/render/cameraModel.ts`）| 地面 → 画素の投影（`config/generate.py` 経由） |
| GUI の「補正」映像 | `telemetry_node` が仮想ピンホール（`undistort_hfov`）に remap して配信 |

**記録（mcap）・📷 撮影・認識ノードは常に魚眼のままの生画像**を使う（補正は GUI 表示だけ）。
式（Kannala-Brandt、OpenCV `cv2.fisheye` と同じ）と「フル画角・下端クロップ前の画素で持つ」約束は `raspi/core/camera_model.py` の docstring が正。

**手順**:

1. 印刷用ボードを作る: launcher の「カメラ校正」→「印刷用ボードを作る」（または
   `.venv/bin/python -m tools.cam_calib --make-board 9x6 --square 0.025 -o board.pdf`）。
   **「実際のサイズ」で印刷し、平らな板に貼り、1マスを定規で測る。** 内側の角点は**片方を偶数・片方を奇数**（両方奇数だと向きが決まらない）
2. 撮る: GUI のタブバーの **📷**。右（主）カメラ（取得中なら左も）の生画像が無劣化 PNG で ~/Downloads に落ちる。
   **20 枚前後、画面の中央・四隅・左右の端に、距離と傾きを変えて**写す（端の写真が無いと RMS が小さくても端のガイドが曲がる。
   ツールの「画面カバー率」を見る）。車もボードも止めて撮る
3. 校正: launcher の「カメラ校正」でカメラ・ボード寸法・実測の1マスを入れ、「写真を読み込む」→「校正」。
   再投影誤差 RMS が 0.5px 未満、補正後のプレビューで直線が直線に戻っていれば「vehicle.toml に書き込む」（`config/generate.py` まで走る）。
   CLI は `.venv/bin/python -m tools.cam_calib --cam front --board 9x6 --square 0.025 ~/Downloads/surge_front_*.png [--write]`
4. 反映: `tools/deploy.sh --restart`（校正値は起動時に読む。io_node は無関係＝E-Stop はラッチしない）

- 校正値はカメラ×レンズごと。カメラを入れ替えたり、ピントリングを回したら撮り直す
- 解像度（`camera_node --size`）や `bottom_crop` を変えても校正値はそのまま使える
- カメラ学習モデル（`ml_cam`・`ml_cam_e2e`）は撮ったレンズの画像に依存するので、**レンズを替えたら再学習が要る**

### 7.1 色むら補正（レンズごとの ISP チューニング）

libcamera の標準のチューニング（`imx219.json`）の色むら補正（ALSC）は**純正レンズ用**。160° 広角にそのまま当てると、
白い壁が「中央は緑・周辺はピンク」に写る。レンズのプロファイルに `isp_tuning = "<ファイル名>"` を書くと、`config/cam_tuning/` の
**差分**（ALSC の表だけ）を標準へ重ねて開く（`raspi/core/cam_tuning.py`）。書いていないレンズは標準のまま。

作り方（レンズを替えた・別のレンズを足したとき）:

1. 白い無地の壁にカメラを向ける。壁が**画面の中心と上の両隅**まで入ること。色の違う光（窓と電球）が混ざらないこと
2. Pi の上で（カメラを掴むので配信を止める）:
   ```
   sudo systemctl stop surge-camera
   .venv/bin/python -m raspi.tools.alsc_calib --cam 0 --rows 0,0.54 --out config/cam_tuning/imx219_<レンズ>.json
   sudo systemctl start surge-camera
   ```
   `--rows` は使う行の範囲（車体が写り込む下側を外す）。`残差σ` が数%なら良い。できたファイルは Mac へ持ち帰ってコミットする
   （`deploy.sh` は Mac → Pi の一方向）
3. プロファイルに `isp_tuning` を書いて `tools/deploy.sh --restart`

- **チューニングはプロセスに1つしか効かない**（libcamera が最初にカメラを数えた時点で全カメラ分を決める）。左右で `isp_tuning` が
  違うと右（主）カメラのものが両方に当たり、起動時に警告が出る。`camera_node` でカメラを開く前に `Picamera2.global_camera_info()` を呼ぶと
  標準に固定されて黙って効かなくなる
- 表は中心からの距離だけの関数。周辺減光と色温度ごとの表は作っていない
- 色が変わるので、色を見る処理（矢印信号の HSV しきい値・カメラ学習モデル）は撮り直し・再調整が要る

### 7.2 ステレオ（前方左右2台）

計画は [`stereo_plan.md`](stereo_plan.md)（段階2）。左右それぞれの内部パラメータと、左 → 右の R・T
（`X_右 = R·X_左 + T`、約束と平行化は `raspi/core/stereo_model.py`）を一度に求める。

1. 撮る: 📷 で右（`front`）と左（`left`）が順に落ちる（ファイル名の時刻が数百 ms ずれる。ツールは 1.5 秒以内を同じ瞬間の組にする）。
   **ボードは両方の画面に入れ、止めて撮る**（同期は要らない）。20 組前後、画面の中央と端、距離 0.3〜1m、傾きを変えて写す。
   片方にしか写っていない写真もその1台の内部パラメータには使われる
2. 校正: launcher の「カメラ校正」でカメラを「ステレオ」にし、「写真を読み込む」→「校正」。
   CLI は `.venv/bin/python -m tools.cam_calib --stereo --board 9x6 --square 0.025 ~/Downloads/surge_{front,left}_*.png [--write] [--preview-dir 出力先]`
3. 合否: **平行化後の対応点の縦ずれの中央値 0.5px 以下、基線 75±2mm**。プレビュー（平行化した左 | 右に緑の横線）で同じ角が同じ線に乗っているかも見る。
   合格のときだけ書き込める: 左右の `[sensors.cam_*.lenses.<レンズ>.fisheye]` と `[sensors.stereo]`
4. 反映: `tools/deploy.sh --restart`

- 縦ずれを 95% 点でなく中央値で見るのは、魚眼の周辺の角点の検出誤差（1px 級）に 95% 点が支配されるため。
  合成画像で、真の R・T でも 95% 点は 0.69px、中央値は 0.10px。R にピッチ 0.1° の誤差を入れると中央値は 0.53px（`tools/cam_calib/calib.py` の `MAX_RECT_DY_PX`）。
  縦ずれは平行化画像（水平 100°）の中に写る角点だけで測る
- 検出器はボードの角点を逆順（180° 回した並び）で返すことがあり、左右で食い違うと R・T が発散する。ツールは組ごとに向きをそろえる（`aligned_left_corners`）
- `[sensors.stereo]` には校正したときのレンズ名（`lens_right`・`lens_left`）が入る。**今のレンズと違えば `Vehicle.stereo` は None**（付け替えたら撮り直す）
- 取付を少しでも動かしたら（ステーの曲がり・カメラの付け直し）撮り直す

## 8. 車速の推定（走行距離＋加速度計のカルマンフィルタ）

STM32 の車速 `speed` は**カルマンフィルタ**（ファームの `src/control/speed_kf.c`）。調整値は `[control]` の `kf_*`
（`CONFIG_SET` で STM32 へ送る。値の出どころは [`control_constants.md`](control_constants.md)）。
**センサの実測だけで決まるのは加速度の雑音の一部だけ**で、走行距離の測定ノイズ `kf_sigma_s_m` は経験値（周期誤差を白色雑音として通さないための水増し）。

1. **記録から最尤推定して決める**: `python -m tools.calib.kf <mcap...> [--apply]`（校正 1 を入れた後の走行の記録を複数）。
   STM32 と同じフィルタ（`tools/calib/kf.py` の `replay`）に TELEMETRY を通し、残差の尤度を最大にする σ・PSD を探して NIS・ρ を出す。
   ρ が 0.3 を超えた測定は白色の前提が破れている（周期誤差・振動）ので書き込まない
2. **調整値を検定する（真値は要らない）**: `python3 -m raspi.tools.kf_consistency <記録>.mcap`。STM32 が窓（10ms）ごとの
   **NIS（平均 z²、1 が理想）** と **隣り合う残差の相関係数 ρ（0 が理想）** を TELEMETRY で送り、区間（静止・低速・中速・高速・
   強い加減速）× 測定（走行距離・加速度）ごとに出る。
   - **ρ が大きい（>0.5）なら NIS では調整できない**（前輪の周期誤差のような系統誤差が残差に残っている）
   - ρ が小さいとき、NIS<1 は保守的、NIS>1 は過小。**値の大きさまでは言えない**（σ だけを √NIS 倍にしても NIS は 1 にならない）
   - 静止の NIS はセンサ自身の白色雑音だけを見ている
3. **前輪エンコーダの周期誤差**: 校正 1 が測って STM32 が角度ごとの補正で直す（§4.1）。TC・ABS の校正はこの KF の車速で行う
4. **生データで調整値を比べる**: `python3 -m tools.fwsim.kf_raw_replay <キャプチャ>.bin [--define SPEED_KF_SIGMA_S_M=...]`
   （2kHz の生データに今の `speed_kf.c` を通す。シムの出力列 `fw_nis_*`・`fw_ac_*` が実機の診断と同じ量）
5. **記録を車速の精度で確かめる**: `python3 -m raspi.tools.speed_est_compare <記録>.mcap`（静止ノイズ・`kf_gated`・加速度バイアスの動き・
   テレメトリ間隔）。基準は `odom_dist` を零位相で平滑して微分（前輪から作るので、**前輪の周期誤差・滑りは測れない**）
6. **制御ループが長く止まったとき**: 前輪の角度差は ±半周に畳むので、止まっている間に半周を超えて回ると 1 回転ぶん折り返す。
   `drive.c` が予測した増分に最も近い側へ 1 回転の整数倍を足して戻す（`tools/fwsim/tests/test_speed_kf_stall.py`）。
   1 秒以上の停止は初期化し直す

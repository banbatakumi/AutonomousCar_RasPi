# 車両の校正（calibration）— 設計と手順

**2026-10-18 に、旧「システム同定」（`tools/sysid`・`tools/ctrl_tune`・`raspi/auto/sysid_*`）を
ここに書く形へ作り直した。** 旧版は試験 9 本・解析 1 万行に育ち、どの値が何に使われ、正しく
測れているかが追えなくなっていた。

## 1. 方針

1. **slam2d の走行に要る値だけを測る。** 使われない値（シムの車の細かい癖）は測らない。
   シムが使う値は `config/vehicle.toml` の `[sim]` に置き、「実機の制御は読まない・同定しない」と明記する
2. **1つの校正は「測る → 決める → 確かめる」の3段。**
   - 測る（同定試験）: 開ループで車体の性質を測る。モデルは物理の式で、パラメータは少なく
   - 決める（設計）: 制御のゲインは**式**で決める（数値最適化の箱にしない）。式の前提も書く。式の前提が実機で成り立たない TC・ABS は、
    式で基準を作って**実機で振って**決める（校正 8）
   - 確かめる（検証試験）: **閉ループで制御そのものの効きを測り、合否を出す**。モデルが合って
     いるかではなく、制御が狙いどおりに効いているかを実機で直接見る
3. **解析そのものも確かめる。** 各解析は「真値の分かっているシムで試験を走らせ、解析が真値を
   復元するか」をテストに持つ（`tools/calib/tests`）
4. 記録はすべて TELEMETRY（100Hz）と指令。新しい計測手段は足さない

## 4. 各校正の中身

### 4.1 エンコーダ（`calib_encoder` → `tools/calib/encoder.py`）

前輪のアナログ絶対角エンコーダ（AS5600）の読み u（ADC÷フルスケール、0〜1）を STM32 が
`lib/encoder_cal` の式で真の角度へ直す:

    θm = (u − lo)/(hi − lo)·2π,   θm = θ + e(θ),   e(θ) = h1s·sinθ + h1c·cosθ + h2s·sin2θ + h2c·cos2θ

**測り方**: 直線でトルク 0 の惰行をさせる。惰行中の車輪の真の回転 θ(t) は転がり抵抗だけで滑らかに
減速するので、**時間の低次多項式**で書ける。読み（TELEMETRY の `front_angle`＝校正前の生の角度）は
θ(t) + e(θ(t)) なので、1 区間ごとの多項式と、全区間で共通の (lo, hi, h1s…h2c) を同時に最小二乗で
当てはめる。惰行 1 回で車輪は数回転するので、角度の関数（周期誤差）と時間の関数（減速）は分かれる。

- なぜ惰行か: 速度制御中は PI が周期誤差を含む車速に合わせてトルクを揺らし、真の回転にも同じ周期の
  うねりが乗る（誤差を小さく見せる）。惰行中は何も読み返さない
- **確かめ方**: 校正を入れた後にもう一度録り、STM32 が出す校正後の走行距離 `odom_dist` に同じ当てはめを
  すると、周期誤差の振幅が測定ノイズ程度まで落ちる（落ちなければ不合格）。速さの違う 2 段の惰行で
  係数が一致することも見る（一致しなければ角度の関数でない誤差＝振動などが混ざっている）

### 4.2 ステア（静特性）（`calib_steer` → `tools/calib/steer.py`）

slam2d は「狙う曲率 → 送る舵角」の換算（`Vehicle.steer_map`）を使う。舵のリンクは線形ではなく、
STM32 がモータ角 x（×リンク比 0.5）を路面舵角 δ = g·x + c·x³ に換算している（`[control] steer_link_*`）。

**測り方**: 低速（0.35m/s）で舵角を固定して弧を走り（前進し、同じ舵のまま後退して元の点へ戻る）、
舵角の段を −最大〜＋最大で振る。低速なのでタイヤの横滑りは無視でき、運動学の関係

    曲率 κ = ヨーレート ÷ 車速 = tan(δ_実) / L

から実際の舵角 δ_実 = atan(κL) が出る。各段で (モータ角 x, δ_実) の組を集め、
δ_実 = g·x + c·x³ + δ0 を当てはめる。δ0 が中立のずれ（`steer_offset_rad`、Pi 側で引く）。
サーボの定常ゲイン `steer_servo_gain` は報告舵角 ÷ 指令舵角（保持中の平均）。
記録時に STM32 に入っていた換算は `/diag/link` から読んで x を戻す（換算を入れ替えても測り直せる）。

- 前進と後退で同じ弧をたどるので、置いた場所から大きく動かない
- **確かめ方**: 入れた後に録り直すと g=1・c=0・δ0≈0 に戻る（残差が段ごとの曲率のばらつき程度）

### 4.3 ステア（動特性）（`calib_steer_dyn` → `tools/calib/steer.py`）

slam2d は「舵を送ってから曲率が付くまでの遅れ」（`Vehicle.steer_delay_s` = むだ時間＋サーボの
1次遅れ＋ヨーの遅れ）を先読みに使う。

**測り方**: 直線を 1.0m/s で走りながら舵を小さく（±6°）方形波で振る。
- サーボ: STM32 がランプさせた参照舵角 `steer_cmd_echo` → 実舵角 `steer_actual` に「むだ時間＋1次遅れ」
- ヨー: 実舵角から出る曲率（4.2 の換算）→ 実際の曲率（ヨーレート÷車速）に2次遅れ（ωn, ζ）

### 4.4 遅延（`calib_latency` → `tools/calib/latency.py`）

止まったまま、スキャンが来るたびに舵の指令の符号を反転し、舵角にスキャンの番号を刻む
（`±(振幅 + 0.002rad×(seq mod 8))`）。スキャンの最後のセクタの受信時刻から、STM32 の
`steer_cmd_echo` がその値になった時刻までが遅れ。旧版と同じ考え方（作り直したのは解析だけ）。

### 4.5 車速制御（`calib_speed`・`calib_speed_check` → `tools/calib/speed.py`）

**車体のモデル**（後輪 2 輪の合計トルク T → 車速 v）:

    T_eff' = (T(t − d) − T_eff)/τ,   v' = G·T_eff − r_±   （r は前進・後退で別）

G は利得（名目 1/(車輪半径×質量) = 16.7 (m/s²)/(N·m)）、r は転がり抵抗の減速度、d・τ は MD の
トルクの遅れ。

**測る**（`calib_speed`、トルク直接指令。PI を通さない）: 前進・後退でトルクの段（加速→小さいトルク→
惰行 0）を掛ける。滑らない強さ（加速度 1.5m/s² 以下）に抑える。走行距離（微分しない）に出力誤差法で
当てはめる。

**決める**（2自由度制御。STM32 の構造はそのまま）:
- FF: `speed_ff_nm_per_m_s2` = 1/G（目標の加速度を出すトルク）、`speed_ff_rr_nm` = r/G（転がり抵抗を打ち消す）
- PI: 一巡伝達 L(s) = G·(kp·s + ki)/s²·e^(−s·Td)（Td = d + τ + 車速の推定の遅れ + 制御周期の半分）。
  交差角周波数 ωc と PI の零点 ωz = ki/kp を、**位相余裕**（既定 60°）から決める:
  位相余裕 ≈ atan(ωc/ωz) − ωc·Td。ωz = ωc/4 と置くと ωc = (76° − 60°)/Td。kp = ωc/G·cos(atan(ωz/ωc))、ki = kp·ωz
- 上限: ωc は `SPEED_WC_MAX`（車速の推定の雑音がトルクに出る大きさで決める）を超えない

**確かめる**（`calib_speed_check`、車速指令。ふだんの走りと同じ経路）: 加速のランプ・定速・減速の
ランプ・段の指令を前進・後退で出し、**実測の追従誤差を、同定したモデル＋決めたゲインのシムの予測と
比べる**。合否: ランプ中の追従誤差・行き過ぎが予測の範囲内で、振動が無いこと。

### 4.6 後輪の空転（`calib_wheel` → `tools/calib/wheel.py`）

後輪を浮かせ、小さいトルクの段で回しては止める。路面の力が無いので J·ω' = T_eff − T_f·sgn(ω) − b·ω から
車輪の慣性 J・摩擦 T_f・粘性 b、MD の遅れ（d, τ）が出る。TC・ABS の設計の材料（車輪の慣性が小さいほど
スリップは速く動く）。

### 4.7 タイヤ（`calib_tyre` → `tools/calib/tyre.py`）

**測り方（2026-10-19 に作り直し）**: TC・ABS を切り（`fw_overrides`。片輪浮き対策の周速 7.5m/s の歯止めは残す）、直線で
トルクを**ゆっくり** 0 から最大（0.13N·m）まで上げる（`dramp`＝駆動 0.5〜1 秒・`bramp`＝制動 0.4〜0.5 秒、各 3 回。
手前の `trim` で定速のスリップ率の偏りを読む）。旧方式は TC・ABS 自身にスリップ率を保たせたが、未調整の制御器は低いスリップ率
を保てず（目標 0.03 でも実際は 0.065 以上）、制御器の揺れが点に載った。一番知りたい肩と傾きが、制御器の出来に左右されて
測れなかった。ランプなら制御器に依らず、低いスリップ率から山の先まで 1 本で測れる（低いスリップ率ではタイヤが硬く、スリップは
力にすぐ追従するので、0.5 秒程度のランプで準静的）。

- スリップ率: STM32 が制御に使っている値（`tc_slip`）の左右別から、`trim` の中央値（前輪の倍率誤差による 0.006〜0.011 の偏り）
  を引く
- 前後力の合計: 車体の加速度から F = m·(a + r_±)（校正 5 の質量・転がり抵抗。車輪の慣性を使わない）
- **駆動**: 各輪の力は車輪の運動方程式 (T − J·ω̇ − T_f)/r（T は各輪のトルク指令。J・T_f は 6）で左右別に出し、各輪の曲線を別々に
  当てはめる。車輪から出した左右の和が車体の合計と合うこと（0.85〜1.15）を確かめる。**目標は弱い輪の肩に合わせる**
  （TC は各輪が同じ目標を使うので、弱い輪の肩まで滑らせないとその輪の力が 95% に届かない）
- **制動**: MD の制動は低い周速でトルクが抜ける（指令と実際が違う）ので車輪から力を出さない。ABS は左右のうち滑りやすい方に
  合わせる（select-low）ので、車体の合計の力を**滑りやすい方のスリップ率**に対して当てはめる（ABS が実際に見る関係）。曲線の形が
  決まらない（係数が下限に張り付く。弱い輪が先に飽和して合計の力が二段に増える左右差の大きい車など）ときは駆動の目標を使う
- 形は F = D·sin(C·atan(B·λ))。λ は真のスリップ率 = STM32 の読み + a·L/v（読みの遅れ L は、低いスリップ率まで測れているので
  「力 0 でスリップ 0」を通すように決まる。基準速度の遅れなどもまとめた見かけの値）

**決める**:
- 目標スリップ率（`tc_slip_target`・`abs_slip_target`）: **ピーク付近 = 力が頭打ちになる点**（文献どおり。乾いたタイヤのピークは 6〜20%、
  Formula Student の 4WD で約 18%）。**測定したスリップ率のまま**（STM32 が TC・ABS に使う値。読みの遅れの補正をしない）、真のスリップ率の順に
  点を同じ数ずつの群に分けた力の中央値が、最大の 95% に届く最小のスリップ率（`empirical_peak`）。上限 0.3（`_TARGET_CAP`。それより先は
  横力をほぼ失う）。TC は各輪が同じ目標を使うので**左右の平均**（バンビ提案。大きい方に合わせると強い輪の保護が緩く、小さい方に合わせると弱い輪の力を削る。
  力は肩の付近でほぼ平ら）、ABS は滑りやすい方。2026-10-20 の実機で、TC は左 0.15・右 0.31（右輪が左の数倍滑る）→ 0.23、ABS は 0.12〜0.20。
  - 山（その先で力が落ちる点）が見えないとき（実機はこちら）も、95% に届く点で頭打ちとみなして★。山がもっと先なら力を少し捨てている
  - 遅れの補正（真のスリップ率 = 読み + |a|·L/v）をした版は目標が 0.08〜0.1 に出て、TC に保たせると加速が 2.9→2.2m/s² に落ちた
    （右輪は力の 95% に届くのに 0.13〜0.25 の読みが要る）。測定値の knee が実際の発進に合う
  - 検討して外した案: 「最大トルクを一気に掛けたときのスリップ率」（TC 0.2〜0.35・右輪 0.65、ABS 0.6。それより下では何もしないのでピーク付近ではなく、
    横力をほぼ失う）。横に残る余力と前後の力を等しくする（約 0.10。直線の加減速が約 7 割）は、直線の試験では横力を測れていないので保留
  - **横グリップへの影響は直線の試験では測れていない**。コーナー立ち上がりで膨らむ場合は目標を下げるか、横加速度に応じて変える（ファームの変更）
  - 曲がっている所は slam2d のライン（`raspi/nav/raceline.py` の摩擦円）が前後の加速度を絞るので、TC・ABS が働くのは主に直線の発進・制動
- **ゲインは校正 7 では決めない**（2026-10-20）。スリップ速度 u = rω − v は、トルクに対してほぼ積分器 (r/J)/s で、その先に MD の遅れが
  ある。位相余裕の式でゲインを決めたら実機で高すぎて振動し、TC・ABS を切ったランプでも制動側の周速はトルクを掛けると
  揺れる（0.03m/s。定速は 0.004）ので、揺れの一部は制御器の外（MD・タイヤ）にあり、式の前提（滑らかなプラント）が成り立たない。
  ゲインは校正 8（§4.8）が実機の閉ループで決める
- **スリップ率の読みの遅れ L**: 駆動の各輪の曲線で決める（中央値。実機 63ms・シム 30〜70ms）。制動の曲線は L が B・C と入れ替わって
  決まらない（探索範囲の上限に張り付く）ので、制動は駆動の L に固定する。校正 6 の MD の遅れの合計（16ms）より大きいのは、
  基準速度の遅れなどを含む見かけの値。**TC・ABS が見るスリップ率はこの分だけ力より遅れる**
- **曲線が標準の式に合わないとき**（係数 C・B が探索範囲の端に張り付く。2026-10-20 の実機では右の駆動と制動）は、形を仮定せず、
  真のスリップ率の順に点を同じ数ずつの群に分けた力の中央値から、最大の 95% に届く最小のスリップ率を目標にする（`empirical_peak`。
  完全に滑った先（真のスリップ率 0.5 超）は含めない）。このとき μ・タイヤの係数・横の上限は書かない
- 横の上限の見積もり（`[limits] a_lat_m_s2`）: μ·g（前後と横の μ が同じ・前後輪の荷重の分担が横力の分担と同じ、を仮定。
  走行中の学習の初期値なので粗くてよい）。山が測った範囲に無いときは書かない

**合否・★**: ランプの間に TC・ABS が働いていたら不合格（切る上書きが STM32 に入っていない）。曲線の点が 12 個未満、スリップ率が
0.15 まで上がっていない（山の先が見えない）、最も低いスリップ率が 0.03 より大きい（肩が見えない）、左右の力の上限の比が
0.8〜1.25 を外れる（弱い輪の荷重・タイヤ・MD を確かめる）、同じトルクで左右のスリップ率が 1.5 倍以上違う、は★。

**決めた値は、ホストでコンパイルしたファーム＋同定した車輪・タイヤのモデル（`host/host_sim.c`）で発進・制動を回して確かめる**
（設計の式が前提を外していないか）。解析は真値の分かるシムのタイヤで目標が肩に出ること・左が弱い車で左が報告されることを
`tools/calib/tests/test_traction.py` で確かめている。

### 4.8 TC・ABS のゲイン（`calib_tc_gain` → `tools/calib/tc_gain.py`）

**ゲインを設計せず、交差周波数 ωc を実機で振って決める。** 基準のゲインは物理から作る（`vehicle.toml` の今のゲインは使わない。
それが壊れた値かもしれないので）。**試験の間だけ目標スリップ率を働く値（TC 0.09・ABS 0.18、`TEST_TARGETS`）に上書きする**（校正 7 の目標が
「最大トルクまで滑らせる」値だと制御器が働かず、ゲインを測れないため）。スリップ速度がトルクに対してほぼ積分器 (r/J)/s なので、交差周波数 ωc を決めれば kp が決まる:

    kp = ωc·J/r,   ki = kp·ωc/ratio       （PI の零点を交差の 1/ratio に置く。ratio = 4 が基準）

J は校正 6 の後輪の慣性、r = 0.030m。現行の kp 0.097 は ωc ≈ 80rad/s に当たる。

**P と I の比（ratio）の決め方**: 零点を交差の 1/4 に置くのは、積分が交差の位相を削る量を約 14° に抑える慣用の値で、実機で確かめた
根拠ではない。I を強く（ratio を小さく）すると目標への収束は速いが位相を削って振動しやすく、弱くすると行き過ぎが残る。
そこで 2 段で決める。

1. **ωc の梯子**: ωc = 15・30・60・120・240rad/s（比 4）で、全開の発進（TC）と最大の制動（ABS）を実走する。**発振**（区間内の
   スリップ率の揺れが 0.04 超で、一つの周波数に 50% 以上集まり、その周波数が 12Hz 以上、かつ**高周波の揺れが手前の片道の最小の 1.6 倍超**。
   12Hz 未満の遅い揺れはゲインが低くて目標に保てていないだけ。**実機は TC・ABS のゲインによらず 20〜30Hz の揺れが常にある**（TC・ABS を
   切ったランプでも制動側は 0.03m/s）ので、「一つの周波数に集まる」だけでは発振と言えない）を片道ごとに見張り、見つけた側は**それ以降の片道で発振したゲインへ戻らない**（最後に良かった値で走る。
   もう一方は上げ続ける）。TC と ABS は別々に進む
2. **比の掃引**: 採る ωc の側で、比を 2.5・8 に変えた片道（比 4 は梯子の片道）

**採り方**（解析）: **ゲイン余裕 2 倍**として、採る ωc は梯子で最初に発振した ωc の半分以下（発振が出なければ梯子の最大の半分以下）。
その範囲の片道（**比を変えた片道も含む**。I を強くすると低い ωc でも目標に保てることがある）のうち、発振せず平均スリップ率が
目標（校正 7）の ±0.04 以内のものから、加速度・減速度が最良の 95% 以上を保つ最大の ωc（高すぎるとトルクが暴れて性能が落ちる）を
採り、同じ ωc の中では始まりの行き過ぎ（スリップ率が目標の 2 倍を超えた時間）が最も短い比を採る。範囲に目標に保てた片道が無ければ
不合格（ゲインを上げると発振し、下げると保てない。校正 7 の目標を下げるか、路面・タイヤ・MD を確かめる）。書き込む値は
`tc_kp/ki`・`abs_kp/ki`。

2026-10-20 の実機（最初の判定は「一つの周波数に集まる」だけで、TC は ωc 120rad/s の 31Hz・ABS は 60rad/s の 28Hz を発振とした）は、
高周波の揺れが ωc を上げても増えていない（TC 0.048→0.066、ABS 0.067→0.088 程度）ので、**発振ではなく、タイヤ・MD の常在の揺れだった**。
タイヤの傾きが急（スリップの極 a が大きい）と、積分器とみなした ωc より実際の一巡のゲインは低く（kp·(r/J)/a < 1）、不安定になりにくい。

制約: 記録の `/diag/link` に入っているのは基準の値で、片道ごとの上書きは指令の `fw_overrides` に残る（解析はそこから読み戻す）。
試験が途切れれば上書きは外れて toml の値に戻る。約 60 秒・直線 2m＋車長。

### 4.9 TC・ABS の確かめ（`calib_traction_check` → `tools/calib/traction.py`）

TC・ABS を入れたまま、直線で全開の発進と最大の制動を 3 回ずつ。

- 合否: スリップ率の平均が目標の ±0.05 以内、ばらつき（標準偏差）が 0.05 以下、振動（トルク上限の
  上下）が続かない
- **実際に出た加速度・減速度の中央値を `[limits] a_accel_m_s2`・`a_brake_m_s2` に書く**（走行中の
  学習の初期値・学習しないときの上限。slam2d は `FIXED_*_USE` の割合を掛けて使う。減速は車速指令（TC）で測る——
  slam2d の減速はこの経路で、ABS は非常時だけ）。予測（4.7 のモデル）と食い違えば★

## 5. 値の置き場所（`config/vehicle.toml`）

- `[control]`・`[dynamics]` の各キーの行末に、**どの校正が書くか**（または「手置き」「ファームの定数」）
- `[control.plant]`: TC・ABS の設計に使う車輪・タイヤのモデル（6・7 が書く）
- `[limits]`: slam2d の横・加速・減速の上限の初期値（7・8 が書く）
- `[sim]`: シムの車の値（実機の制御は読まない・同定しない）

## 6. 使い方

1. 実機: GUI の「システム同定」タブで試験を選び「試験開始」→ ARM を保持 → 終わったら記録が落ちてくる
2. Mac: `launcher.command` →「車両の校正」（`tools/calib/gui.py`）で記録を開くと、解析・所見・合否・
   書き込む値の一覧が出る。「適用」で `config/vehicle.toml` に書く
3. `./tools/deploy.sh --restart-io` で Pi に反映（`[control]` は接続のたびに STM32 へ送られる）

コマンドで回すなら `python -m tools.calib <記録.mcap>`（試験の種類は記録から判別する）。
